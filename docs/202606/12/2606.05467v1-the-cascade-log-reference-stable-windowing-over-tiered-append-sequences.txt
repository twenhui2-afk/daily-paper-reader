# The Cascade Log: Reference-Stable Windowing over Tiered Append Sequences 

Faruk Alpay ∗ Levent Sarıoğlu 

Department of Computer Engineering, Bahçeşehir University, Istanbul, Turkey 

{faruk.alpay, levent.sarioglu}@bahcesehir.edu.tr 

Abstract 

A long-running, append-mostly sequence of records—edits in an interactive session, events in an event-sourced store, revisions in a version-controlled working set—cannot be kept fully materialised, so it is layered into tiers: a hot working set over progressively colder strata into which aged records are folded and summarised. Records nonetheless carry stable handles that are referenced across tier boundaries, and resolving a handle must stay correct as its target migrates downward. We show that the obvious tiered design silently violates this requirement at exactly the tier boundaries: under a realistic access mixture a quarter of cross-window references resolve to a stale, wrong, or absent record, and after sustained folding more than ninety-eight percent of the history becomes unaddressable. The Cascade Log removes these failures. A single persistent coalescing interval map over handles is the sole authority on each handle’s live version; folding coalesces a contiguous run into one interval node in a single split–merge splice. Our central result is a tight characterisation of this structure by its fragmentation 𝐴 —the number of index pieces, namely live handles plus maximal same-digest runs. The map uses Θ( 𝐴 ) space, resolves a point in 𝑂 (log 𝐴 ), reports a 𝑘 -handle range in 𝑂 (log 𝐴 + 𝑘 ), and updates in 𝑂 (( 𝑎 /𝐵 + 𝑠 ) log 𝐴 ) over 

𝑎 appends and 𝑠 supersedes; matching Ω( 𝐴 ) space and Ω(log 𝐴 + 𝑘 ) query lower bounds hold for any 

reference-stable, ordered, bounded-working-set structure, and an adversary forces 𝐴 = Θ (𝑠 ). The index is thus instance-optimal— 𝑜 (𝑛 ) when appends dominate, Θ(𝑠 ) under adversarial edits, and then no structure does better. Resolution is total, snapshot-consistent, and anomaly-free; the working set is independent of history length; and the design transfers to external memory at 𝑂 (log 𝛽 𝐴 ) I/Os. A reference implementation and a reproducible study to 10 6 records, including adversarial and distribution-free workloads and a copy-on-write ordered-map baseline, trace 𝐴 directly and confirm the bounds. 

# 1 Introduction 

Many systems are organised around a single growing sequence of immutable records that is appended to far more often than it is read in full: the edit history of an interactive session, the event log of an event-sourced application, the revision stream of a version-controlled working set, the chunk sequence of an incremental indexer, the tuple stream of a continuous analytic query. The sequence quickly outgrows fast memory, so it is tiered . A bounded hot stratum holds the recent records fully materialised; aged records are folded in contiguous blocks into colder strata, where a block is replaced by a compact digest that summarises it. Tiering is what keeps the materialised working set bounded as the history grows without limit, and it is the same idea that underlies log-structured storage [19].

The records are not independent. Each carries a stable handle , and records reference earlier handles: an edit refers to the region it revises, an event to the entity it mutates, a derived chunk to its source. A consumer resolves a handle to obtain the record’s current version, and assembles a bounded window of related records around a query. The difficulty is that references cross tier boundaries. A handle minted while its target was hot is followed later, after the target has been folded into a cold digest; a handle is edited after the block holding it was already summarised; a window is assembled while a fold is in flight. At each of these boundaries the obvious tiered design fails in a way that is easy to miss because every individual tier is internally consistent—the defect lives only in the transition between tiers. We make the failure precise as three cross-tier reference anomalies . A dangling resolution returns nothing for a handle that was appended and never deleted, because folding reclaimed its addressing entry. A stale 

resolution returns a superseded version, because no tier holds the authoritative one. A snapshot-skew window mixes records read before and after a fold and is therefore not a consistent view of any single instant. Section 6 quantifies them: with a hot stratum of a few hundred records over a history of tens of thousands, a tiered log leaves under two percent of the history addressable and mis-resolves roughly a quarter of references drawn from a realistic access mixture. This paper presents the Cascade Log, a tiered append structure for which resolution is provably free of all three anomalies while the working set stays bounded. Three ingredients combine: 

• a versioned interval index (Section 3.1)—one persistent search tree, shared across snapshots by path copying [ 13 , 23 ]—which spans every stratum and is the single authority on where each handle’s current version lives, so resolution never depends on the order in which tiers are probed; 

• a coalescing interval map (Section 3.2)—folding a contiguous run collapses it to a single interval node in one 𝑂 (log 𝑛 ) splice, so compaction is amortised 𝑂 (1) per appended record and the index is sublinear, while a folded handle still resolves through its digest; and 

• snapshot tokens (Section 3.3)—immutable roots that serve reads as of any past instant, making windows consistent by construction. Windows are chosen (Section 3.5) by diffusing relevance from the query over the reference graph with a personalised random walk [ 9, 14 ] and then solving a standard budgeted maximum-coverage instance over the candidates [ 16 , 18 ]. The selection layer applies known algorithms; our concern is the structure beneath it that keeps the candidates resolvable, snapshot-consistent, and cheap to gather.

# 2 Model 

Records, handles, versions. The structure stores a sequence of records appended over time. Appending a record mints a fresh handle from a monotonically increasing counter; the 𝑘 -th appended record has handle 𝑘 .A record may be superseded by a later version of the same handle, modelling an in-place edit, so a handle denotes a logical record whose content evolves through versions 0, 1, 2, . . . Each handle ℎ carries a set of out-references 𝑅 (ℎ) to earlier handles; the directed graph 𝐺 = (𝑉, 𝐸 ) with 𝐸 = {( ℎ, ℎ ′) : ℎ′ ∈ 𝑅 (ℎ)} is the 

reference graph .

Strata and folding. Records occupy a sequence of strata 𝑇 0, 𝑇 1, . . . with the hot stratum 𝑇 0 holding the recent records fully materialised. When the number of materialised records exceeds a capacity 𝐶 , the oldest are demoted; once a block of 𝐵 demoted records accumulates it is folded into a digest , a fixed-footprint object that summarises the block. A cost 𝑐 (ℎ) > 0 (think bytes or tokens) is charged for each materialised version; a digest costs 𝑂 (1) irrespective of 𝐵 .

Operations. A structure supports Append ( 𝑝, 𝑐, 𝑅 ) → ℎ, Supersede (ℎ, 𝑝, 𝑐 ) → 𝑣 , Resolve (ℎ, 𝜏 ) return-ing the version of ℎ live at instant 𝜏 (or the current instant), and Window (𝑞, 𝛽 ) returning a budgeted set of records relevant to a query handle 𝑞 within cost budget 𝛽 .

Persistence model. Updates ( Append , Supersede , fold) apply only to the newest version and produce a linear sequence of versions 𝐷 0, 𝐷 1, . . . ; we index them by an integer epoch , the count of updates applied. The structure is therefore partially persistent in the sense of Driscoll et al. [13]: any past epoch is read-only and queryable, but the history does not branch—there is no operation that forks an alternate timeline. A 

snapshot token names an epoch; Resolve (ℎ, 𝜏 ) with a token reads version 𝐷 𝜏 . We make the retention policy explicit because it governs both correctness and space: 

• Ephemeral mode retains only the current epoch. Past epochs are not queryable, and a version superseded by a later update becomes unreachable and is reclaimed; the space bound (Theorem 4.7) is stated for this mode. 

• Retained mode keeps a caller-chosen set of tokens; the epochs they name remain queryable, and the path-copied state they reach is kept alive and counted in the space bound. Reclamation is by reachability from the current root and the retained tokens (reference counting suffices, as the version graph is acyclic). Definition 2.1 (Cross-tier anomalies) . A resolution of an existing handle ℎ at instant 𝜏 is dangling if it returns nothing; stale if it returns a version 𝑣 < ver ★𝜏 (ℎ); corrupt if it returns a different handle or, for a materialised result, a payload other than pay ★𝜏 (ℎ). # 3 The Cascade Log 

Figure 1 shows the structure. A single index spans all strata; folding moves payloads downward but leaves the index total; immutable roots capture snapshots.

3.2 Folding by coalescing runs 

When records age out of the working set they are demoted; once a block of 𝐵 has accumulated it is folded. Folding a maximal contiguous run [𝑎, 𝑏 ] of demoted singletons is a single summarise : the run is split out of the map and one interval node spliced back in its place, in 𝑂 (log 𝑛 ) regardless of 𝑏 − 𝑎 + 1 (Algorithm 1). An append-dominated stream demotes contiguous handles, so a whole block folds in one splice; edits that re-materialise old handles break runs, and each such fragmentation is one extra splice charged to the edit (Theorem 4.7). The bulky payloads leave the working set; what is retained, per folded handle, is its exact version inside the digest. Line 4 is the mechanism: a run collapses to one node in a single split/merge, so the index work to fold a block is one splice per contiguous run, not one update per handle. A design that instead rewrites each handle’s entry—a hash spine (Section 5), or any per-key forwarding scheme—keeps a linear index and does Θ(𝐵 )

index work per block; Theorem 4.7 charges the difference. 

Digest semantics. A digest stores, for each handle it covers, that handle’s exact version and a faithful summary of its payload (line 3); the summary is a function of the folded bytes, not an arbitrary value. Resolution therefore returns the correct handle and version for a summarised record always, and the summary in place of the original bytes—the only approximation folding introduces, and one an application opts into by choosing summary (the identity map makes the digest lossless). 3.3 Snapshots and resolution 

A snapshot is taken by retaining the current immutable root as a token; holding a token keeps that version of the vii alive. Algorithm 2 resolves a handle against the current root or any token in 𝑂 (log 𝑛 ): it locates the entry and returns the materialised payload (live) or the digest-backed view (summarised). Resolving every member of a window against one token yields a view of a single instant. Appending splices a fresh maximal singleton in one pass; superseding makes the handle a live singleton, so the new version is authoritative the instant it is written, regardless of any older copy lingering in a digest. 

3.4 Cross-tier range reporting 

Reporting all handles in a key range that straddles the working set and several digests is an in-order traversal of the vii between two endpoints, expanding each summarised interval it meets, and costs 𝑂 (log 𝑛 + 𝑘 ) for 𝑘 

reported handles. A per-stratum design would search each stratum’s index separately; the classical way to recover a single logarithmic search across ordered layers is fractional cascading [ 11 ], and layered probabilistic search lists are an alternative [ 20 ]. The Cascade Log attains the 𝑂 (log 𝑛 + 𝑘 ) bound directly because its one ordered map already spans the working set and the digests. A hash index over handles cannot report a key range at all without enumerating its whole contents.

The prefix heuristic—taking records in decreasing relevance until the budget is spent—ignores both cost-effectiveness and the overlap between revealed contexts, and has no constant-factor guarantee (Proposition 4.14). The guarantee is over the candidate pool C( 𝑞 ) the diffusion produces and the cost–coverage instance on it; it does not bound the loss from candidate generation—from truncating the personalised-PageRank neighbourhood, or from an optimal record lying outside C( 𝑞 ). The cost 𝑐 (𝑢 ) is a single static weight standing for a record’s logical size, its materialisation cost, and the digest lookup a summarised record incurs; budgeted coverage treats it as fixed, while the live structure has tier-dependent access costs, so the guarantee is exact for the abstracted instance and indicative for the system. # 4 Analysis 

Throughout, 𝑛 is the number of handles ever appended. 

Theorem 4.1 (Totality) . For every handle ℎ and every instant 𝜏 at or after ℎ’s append, Resolve (ℎ, 𝜏 ) returns a defined view with identity ℎ.Proof. We show the invariant that the live root contains an entry for every appended handle. Appending inserts 7a live singleton. Superseding makes the handle a live singleton, preserving presence. Folding (Algorithm 1, line 4) replaces a run of live singletons by one summarised interval node naming a digest that retains every handle’s version; the handles stay covered and the digest is never discarded. No operation removes a handle from the map. Hence the live root, and by persistence every root derived from it at an instant 𝜏 ≥ append (ℎ),covers ℎ, on which Algorithm 2 returns a defined view with identity ℎ. □

Theorem 4.2 (Snapshot consistency) . Fix a retained token naming epoch 𝜏 . Every resolution against that token returns the value prescribed by the canonical sequential execution truncated after its first 𝜏 updates. Consequently a window all of whose members are resolved against one token is a consistent snapshot of epoch 

𝜏 and is never snapshot-skewed. Proof. A token is an immutable root produced by path copying: each update derives a new root from the previous one without mutating any existing node [ 13 ]. Hence the root at epoch 𝜏 is, node for node, the tree obtained by applying exactly the first 𝜏 updates of the linear history (Section 2); reading any set of handles against it returns the state after update 𝜏 and no later update. A window built from one token therefore cannot mix pre- and post-fold states. □

Remark 4.3 (Concurrent readers) . The structure as specified is sequential, but its immutability gives the single-writer, many-reader model for free, and that model is exactly the read path of multiversion concurrency control [ 6 ]: a writer serialises updates and publishes each new root with one atomic pointer store, while readers load the pointer once and traverse the immutable tree it names. Readers never block, never coordinate, and each observes a consistent snapshot; every operation linearises at its publish (writer) or load (reader), so the object is linearizable in the sense of Herlihy and Wing [15] . This is the regime the motivating applications read in—snapshot-isolation queries and time-travel reads run against exactly such immutable versions—and the working set keeps a writer’s update local. A multi-writer, lock-free design, where concurrent writers merge into one version order, is genuinely open and is the main limitation of the present primitive. 

Theorem 4.4 (Anomaly-freedom) . No execution of the Cascade Log produces a dangling, stale, corrupt, or snapshot-skewed resolution. Proof. Dangling is excluded by Theorem 4.1. For stale and corrupt, fix a token at instant 𝜏 and a handle ℎ; in that root ℎ carries the version written by the most recent append or supersede of ℎ at or before 𝜏 , since both write ℎ as a live singleton and folding copies the version verbatim into the digest. Algorithm 2 returns exactly that version and the handle ℎ, with a payload that is the materialised value when live and the faithful digest summary when summarised; hence the version equals ver ★𝜏 (ℎ), the identity is ℎ, and a materialised payload equals pay ★𝜏 (ℎ). So no resolution is stale or corrupt. Snapshot-skew is excluded by Theorem 4.2. □

The three guarantees above are by construction: a single authoritative map that never discards a version makes them near-immediate, and we claim no subtlety in the invariant proofs. The substance is the cost 

at which they hold (Theorem 4.7) and the sense in which that cost is forced. How cheaply can a folded handle’s version be kept? Theorem 4.5 answers this and is best read as a space statement that no lossy payload summary can evade: a structure free to summarise payloads arbitrarily must still retain Ω(𝑛 log 𝑡 ) bits to recover exact versions across folds. It is a supporting bound on the cold digests—it shows versions cannot be lossily compressed—and is deliberately not the structural claim: the bound that pins down the index and establishes optimality of the interval representation is the fragmentation trade-off (Theorem 4.10), and the cost of ordered access is Theorem 4.6. Theorem 4.5 rules out only the economy of summarising versions along with the payloads they annotate. 8Theorem 4.5 (Space lower bound for exact versions across folds) . Because the recent records are the cheapest to resolve and the most often queried, the Cascade Log also exhibits the working-set behaviour studied for self-adjusting structures [ 25 , 26 ]: queries that stay within the hot stratum touch only materialised payloads. 12 5 Implementation 

The reference implementation is a self-contained Python package. The vii is a path-copying treap (standard library only); the Cascade Log adds the strata, folding, digests, and windows. Four comparison structures share the operation interface. Flat keeps every version materialised in one table. NaiveTier keeps a bounded hot table over a cold tier that is folded by discarding all per-handle state; ForwardTier adds a never-reclaimed per-handle version counter, which restores version authority but not addressability. The progression NaiveTier →ForwardTier →Cascade Log isolates the two mechanisms—version authority and post-fold addressability. HashSpine is the strong baseline: it is the Cascade Log stripped of persistence and order, a single hash map that is the sole version authority and retains the same constant-size spine through folding. It is therefore anomaly-free and bounded in working set, and resolves in expected 𝑂 (1), matching the Cascade Log on every current-state metric; what it cannot do is read a past epoch (it keeps no version history) or report an ordered key range across strata in 𝑂 (log 𝑛 + 𝑘 ) (a hash imposes no order). It isolates precisely what the persistent, ordered index buys. An independent oracle tracks the exact current and historical version of every handle and classifies each resolution by Definition 2.1. All workloads and measurements are seeded and reproduce bit-for-bit; the package, the result files, and the figure scripts accompany the paper as ancillary files.

Summary. Among designs that bound the working set, HashSpine and the Cascade Log are the anomaly-free ones; the tiered baselines that are not lose almost the entire history. Multiversion and temporal indexing. Serving a read as of a past instant is the business of multiversion concurrency control [ 6] and of versioned and temporal indexes—the asymptotically optimal multiversion B-tree [ 4 ] and the access methods surveyed by Salzberg and Tsotras [22] —which answer time-travel queries at scale and concurrently. These index opaque keys and keep every version; the Cascade Log differs in the two ways that define its niche. It bounds the materialised working set by lossily summarising aged records (Theorem 2.1), trading payload fidelity for a footprint independent of history length, where a multiversion B-tree retains every version in full; and it guarantees reference integrity , a stable handle resolving to the right version across the compaction that summarises its target, which the versioned-index literature does not pose because its keys neither migrate nor summarise. The two are complementary: a multiversion B-tree is one concurrent, external-memory realisation of the persistent ordered map the Cascade Log needs (Theorem 4.12), and the Cascade Log’s own contribution is the coalescing fold and the cross-tier guarantees layered on it. 

Layered search. Searching ordered layers in one logarithmic pass is the province of fractional cascading [ 11 ]and of probabilistic layered lists [ 20 ]; B-trees give the external-memory counterpart [ 12 ]. The Cascade Log’s cross-tier reporting reaches the same 𝑂 (log 𝑛 + 𝑘 ) through a single multiversion index, and any of these techniques may realise it over per-stratum indexes instead. 

Ranking and selection. Diffusing relevance by a personalised random walk is personalised PageRank [ 9 , 14 ]; choosing a budgeted subset that maximises a submodular coverage is budgeted maximum coverage [ 16 ], whose greedy inherits the classical 1 − 1/𝑒 analysis for submodular maximisation [ 18 ]. The window of Section 3.5 composes the two over the reference graph and recovers prefix-by-rank as the modular special case.

# 8 Conclusion 

A tiered append sequence keeps its working set bounded, but the obvious way to do so discards the per-record state that lets handles resolve across tier boundaries, and the result fails exactly where the tiers meet. The Cascade Log shows that the two goals are compatible at a price that is provably small: a persistent interval map as the single authority on every handle, folding that coalesces a run into one node in a single splice—so compaction is amortised constant per appended record and the index is sublinear—and digests that keep each handle’s version, the information a lower bound shows is irreducible. The result is resolution that is total, snapshot-consistent, and anomaly-free at logarithmic cost, with a working set independent of history length; the budgeted window is a standard maximum-coverage instance layered on top. The reference implementation is single-threaded and pays the constant factor of a pure-language persistent tree; a concurrent, de-amortised, external-memory realisation (Section 7), and digests that compress versions succinctly, are natural next steps. 

Reproducibility. The implementation, the seeded workloads, the oracle, the benchmark harness, the raw result files, and the figure scripts are provided as ancillary files; a single command regenerates every number, table, and figure (Section A).
