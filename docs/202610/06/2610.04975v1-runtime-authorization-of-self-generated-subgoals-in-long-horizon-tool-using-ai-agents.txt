# Runtime Authorization of Self-Generated Subgoals in Long-Horizon Tool-Using AI Agents 

GENLIANG ZHU, Accentrust, Canada and Georgia Institute of Technology, USA 

CHU WANG, Accentrust, Canada and University of Illinois Urbana-Champaign, USA Long-horizon, tool-using AI agents create subgoals, replan, delegate work, and compose sibling results. This creates an authorization gap: per-tool permission checks cannot establish that a changing goal graph remains within the principal-approved task. We study this gap in a finite structured domain with one principal and one authorization root. Each proposed goal-graph mutation carries a version-bound witness that its continuation traces, resources, obligations, active invariants, and closing condition refine the active root task contract; each protected effect is rechecked at an atomic commit boundary. Free-form goal text supplies no authority. We prove root trace-policy and modeled forbidden-state preservation under explicit mediation, abstraction, freshness, and atomicity assumptions, plus conditional root-success preservation, a separation result for memoryless allowlists, exact finite-domain decidability, and universal-safety monotonicity under sound abstraction refinement. An executable model explores 340 states and 419 transitions. We evaluate 96 matched cases spanning 25 structural schemas; 24 of 48 templates map to frozen identifiers from four public benchmark artifacts. The complete mechanism commits zero forbidden states in 48 drifted cases and completes all 48 benign counterparts. Two public upstream runtime paths execute 258 native dispatches across 32 cases, with every case-level decision and receipt chain matching. In a separately frozen host-local study, all 129 synthetic one-factor-at-a-time cells match their fixed decision and reason; the resulting curves characterize the finite profile rather than production scalability. A history-aware continuation comparator blocks every modeled bad trace prefix yet commits all operations in 11 cases whose violations lie in typed resources, freshness, or explicit-join evidence outside its trace projection. Within the registered structured domains, runtime authorization preserves useful replanning while preventing self-generated subgoals from becoming a source of new authority. 1 Introduction 

Tool-using AI agents increasingly execute tasks that extend beyond one model response or one API call. A long-running agent may decompose a request, delegate work, revise its plan after an observation, recover from a failed operation, and combine the outputs of several subgoals before producing an external effect. These capabilities improve task completion, but they also change the unit that authorization must govern. A permission check on the next tool call answers whether that call is locally admissible. It does not, by itself, answer whether the growing goal graph still implements the task the principal authorized. This distinction matters whenever policy is non-compositional. Two writes can each target an allowed field while their joint state violates a separation constraint. A recovery action can use an allowed tool yet widen the resource scope from one account to every account. A delegated task can preserve the parent’s vocabulary while replacing its completion condition with an easier proxy. A stale plan can remain locally valid after the policy or relevant environment state has changed. In each case, an allowlist or independent per-call classifier can accept every action even though the authorized task has been expanded through planning.

The classical literature already supplies the relevant foundations. Execution monitoring charac-terizes policies enforceable from traces [27, 32, 38]; hierarchical planning gives formal accounts of task decomposition and refinement [17, 18]; and safety and liveness separate finite bad prefixes from eventual progress requirements [4]. Recent peer-reviewed agent benchmarks show that real-istic tool use is stateful, multi-step, and vulnerable to adversarial or policy-violating trajectories [14, 22, 29, 36, 40, 41, 46]. The open systems question is therefore not whether sequence-aware policies exist. It is how to connect a dynamically changing, agent-produced goal graph to a reference monitor so that planning changes become authorization events and protected effects remain inside the original structured task contract. 

1.1 Problem statement 

We study one principal, one approved root task contract, and a finite structured effect domain. The root contract fixes required and forbidden state predicates, resource bounds, outstanding obligations, temporal limits, and a prefix-closed language of permitted effect traces. The planner and its generated natural-language explanations are untrusted. Before a proposed child, replacement, delegation, or same-root join becomes active, the agent must submit a structured goal description and a checkable transition witness. The witness establishes that the proposed continuation is no broader than the current authorized continuation, preserves active invariants and obligations, and was derived for the current policy and state versions. Every protected effect is then mediated against the active goal and the residual permitted trace language. The paper does not infer authority from free-form text. An upstream component may translate a user request into a structured contract, but the principal or a trusted policy service must approve the structure used for enforcement. This boundary keeps the security claim decidable and auditable: the mechanism checks refinement in a registered finite domain rather than claiming general natural-language entailment. 

1.2 Why local authorization is insufficient 

Consider a task that permits changing either a deployment artifact or its traffic target during diagnosis, but forbids publishing unreviewed code to the production target. The first update is locally permitted, as is the second. After the first update, however, the second must be rejected unless a review obligation has been discharged. A memoryless action allowlist observes the same second action in both the safe and unsafe histories and must return the same decision. A final-state checker can detect the violation only after both effects have committed. The missing state is not another textual warning; it is the authorized composition of the current prefix and the still-reachable future effects. Section 2 gives the executable minimal case and its matched benign trace. 

1.3 Approach 

We represent the approved task and every proposed subgoal in one typed effect and state vocabulary. A goal node records its parent, success predicate, resources, obligations, active frames, policy/state versions, and a finite set of maximal completion traces whose prefix closure denotes the remaining continuations. An ordinary transition is checked along one fresh leaf-to-root witness path; sibling continuations are composed only by an explicit join request whose admissible interleavings are enumerated. Authorization checks the proposed edit against every residual ancestor language on that path. A definite counterexample returns Deny; an unsupported or resource-exhausting decision returns Indeterminate; and a relevant policy or observed-state version change suspends the execution until Reauthorize. Changing the root contract instead starts a new execution epoch. Only Allow makes the transition active. Runtime Authorization of Self-Generated Subgoals 3

The mechanism is external to the planner. It therefore does not depend on a particular prompting method, model provider, or disclosure of private chain of thought. Its trusted computing base is limited to the contract registry, transition checker, effect normalizer, state/version source, receipt store, and commit adapter. The model, planner, retrieved content, worker agents, and free-form goal text remain untrusted. 

1.4 Contributions 

This paper makes six contributions: (1) It identifies a precise authorization gap between locally permitted tool calls and globally per-mitted goal evolution, and supplies an executable matched counterexample in which identical current actions require different decisions because their prefixes differ. (2) It defines a structured semantics for a root task contract, a versioned goal graph, transition witnesses, and residual permitted trace languages. Goal creation, replacement, delegation, and same-root joining are treated as authorization-relevant state changes rather than planner-only bookkeeping. (3) It proves root-policy safety under explicit mediation, abstraction, freshness, and commit assump-tions; conditional preservation of required terminal predicates; a standard insufficiency result for memoryless local checks; a terminating exact decision procedure for registered finite domains; and monotonicity of the universal-safety subcheck under sound abstraction refinement. (4) It implements the transition protocol, an independently implemented trace checker, bounded state exploration, targeted security mutants, and six specified comparison mechanisms. (6) A separately frozen secondary study probes the finite reference envelope over 129 synthetic one-factor-at-a-time cells. 2.2 System boundary 

The protected system has one trusted principal and one approved root task contract. The contract is expressed in a registered finite vocabulary of state predicates, normalized effects, resources, obligations, and versions. The agent may construct a directed acyclic goal graph below that root. It may create a child, replace an active goal during replanning, delegate a child to another worker operating under the same root, join same-root sibling results, cancel work, and close a goal. Each operation is explicit and receipt-bearing. Protected external effects pass through a commit adapter. Read-only observations can also be registered when their values affect authorization, but the principal safety property concerns normalized external effects that cross the adapter. Effects outside this mediation boundary are outside the execution represented by the model; the implementation therefore exposes a fail-closed interface rather than claiming control over unregistered channels. 2.3 Adversary 

The adversary may control the planner’s proposed goal graph, free-form goal text, retrieved content, intermediate memory, worker output, ordering of requests, retries, and proposed effect arguments. It may attempt to: 

• broaden a child’s resources, effects, success predicate, or duration; 

• split an unauthorized outcome across individually plausible siblings; 

• replace a failed goal with a proxy that is easier to satisfy; 

• reuse a witness after relevant state or policy changes; 

• present another root’s child as a compatible delegation or join; 

• commit an effect before its transition is authorized, or replay a previously accepted request with different semantics. The adversary cannot compromise the trusted registry, checker, state/version source, receipt store and its integrity anchor, effect normalizer, or commit adapter; rewrite the retained hash-linked receipt sequence without detection; or bypass the registered effect boundary. The reference artifact provides tamper evidence under that trusted-storage assumption; it does not implement public-key origin authentication. Denial of service remains possible because fail-closed authorization permits the checker to block execution when evidence is incomplete. 

2.4 Security and functional properties 

The primary security property is prefix safety: every committed prefix and every trace still admitted by the active goal’s sound continuation abstraction remain in the root contract’s permitted trace language and avoid its modeled forbidden states. This property is independent of task completion. The functional property is conditional: when every authorized child closes under a valid refine-ment witness, active invariants hold at every registered prefix, residual work and obligations are discharged, and the root closes, the root’s required terminal predicates hold. The result does not require an agent to find a plan or to terminate; it prevents successful closure from being claimed through a non-refining structured goal graph. 

2.5 Scope 

The study covers single-root, single-principal authorization in finite structured domains. It directly covers create, replace, same-root delegate, same-root join, invalidate, effect authorization, effect commit, cancel, and close transitions. Natural-language-to-policy compilation, ethical evaluation of the principal’s request, unmodeled physical consequences, compromised trusted components, and combination of independent authorization roots are separate problems. These scope choices keep the stated theorem and the executed implementation aligned. 

3 Background and Related Work 

This work connects three established lines of research: reference-monitor and trace-policy enforce-ment, hierarchical planning and formal refinement, and safety evaluation for tool-using agents. We use these foundations to answer a specific systems question: how an enforcement service should decide whether an untrusted agent may change the structured objective under which later protected effects will execute. 

3.1 Authorization and trace enforcement 

Complete mediation and least privilege require security-relevant operations to be checked at an authoritative boundary [37]. Authorization logics make principals and delegated authority explicit [1], while usage control accounts for decisions that remain conditional on mutable attributes during 6 Zhu and Wang 

use [35]. History-based access control further establishes that the same current operation can require different decisions after different prefixes [16]. These results motivate the protected-effect adapter and versioned decision context in this paper, but they do not define authorization over changes to a planner’s goal graph. Trace enforcement supplies the closest formal foundation. Security automata characterize an important class of policies enforceable from execution prefixes [38]; edit automata broaden the available interventions [32]; and later work sharpens the boundary between monitorable and enforceable policies [7]. Runtime verification provides verdicts from finite observations [8, 27]. The safety/liveness distinction is therefore material: a finite bad prefix can justify blocking, whereas eventual task progress is not guaranteed merely by preventing bad prefixes [4]. Our primary theorem is a safety result under complete mediation and sound abstraction; the separate success theorem is conditional on closure and does not assert termination. Finite-trace temporal logic gives standard semantics for bounded executions [19]. Temporal logic has also long constrained planning and reactive control [6, 25], and shielding can prevent an unsafe next action, including under partial observability [5, 11]. Thus, neither temporal policies nor online intervention is a novelty claim here. The additional object checked in this paper is a proposed change to the authorized goal structure and its modeled continuations, before that change can make new protected effects reachable. 

3.2 Hierarchical planning and refinement 

Hierarchical task network (HTN) planning recursively decomposes abstract tasks according to domain methods. Its formal complexity, representative planning systems, and design space are well established [9, 17, 18, 33]. Hierarchical goal network (HGN) planning instead gives decomposed goals state-based semantics and explicit method-correctness conditions [39]; recent work extends HGN reasoning to stochastic outcomes [12]. Refinement mappings likewise predate the present setting [2]. These formalisms explain how trusted domain knowledge can structure planning. They do not, by themselves, answer whether a decomposition proposed at runtime by an untrusted agent is authorized under a security mandate, whether evidence for that decision remains current after a policy or relevant-state change, or whether a protected effect still matches the active authorized goal at commit time. This paper therefore does not introduce a planning formalism. It uses a registered finite transition model and ordinary refinement obligations as inputs to an authorization decision over dynamic graph mutations. 

3.3 Tool-using-agent security and long-horizon evaluation 

Peer-reviewed environments now support substantially stronger evaluation than author-written demonstrations alone. ToolEmu emulates high-stakes tool interfaces for scalable risk discovery [36]; AgentDojo jointly evaluates utility and prompt-injection security in a stateful tool environment [14]; InjecAgent and Agent Security Bench broaden indirect-injection and attack/defense evaluation [47, 48]. SafeArena supplies paired benign and harmful web tasks [41]. AppWorld, WebArena, OSWorld, and 𝜏 -bench provide multi-step app, web, computer-use, and tool–user interaction tasks with external state or task-success checks [40, 45, 46, 49]. These sources motivate the independent task origins and state-based oracles in our evaluation; success on one environment is not treated as evidence of universal safety. Long-horizon evidence is now available in formal proceedings as well as preprints. AgentLAB evaluates adaptive attacks including objective drift, tool chaining, task injection, and memory poisoning [22]. MT-AgentRisk evaluates harmful multi-turn tool use and a tool-oriented defense [29]. Goal misgeneralization and uncertainty about the intended reward provide related evidence Runtime Authorization of Self-Generated Subgoals 7

that optimizing a learned or inferred objective can diverge from the designer’s intended result [20, 26]. These works establish the practical importance of sequence-level evaluation. They do not make every long execution unsafe, and their threat categories are prior work rather than contributions of this paper. Recent preprints add trajectory-focused evidence. ATBench and HINTBench study trajectory-level and intrinsic non-attack failures [31, 43]. SafetyDrift predicts violation risk from accumulated trajectory state [15], while the Constraint Drift position paper argues that constraints must remain operative across memory, delegation, tools, and audit boundaries [28]. We use these preprints to delimit current questions and potential evaluation cases, not as substitutes for the peer-reviewed foundations above. 

3.4 Runtime controls for language-model agents 

Several recent systems are direct technical neighbors. AgentSpec, published at ICSE 2026, provides a language and runtime for customizable agent constraints [42]. Formal Methods Meet LLMs, published at FAccT 2026, applies temporal-logic auditing, monitoring, prediction, and intervention to advanced AI systems [3]. CaMeL, published at SaTML 2026, separates trusted control flow from untrusted data and uses capabilities to constrain tool-mediated information flow [13]. These peer-reviewed systems rule out claims based only on a policy language, temporal monitoring, runtime intervention, or capability-gated tool calls. CaMeLoT translates an agent-generated plan to a finite-state transition system and checks temporal policies before execution [34]. Its arXiv record reports acceptance at CAMLIS 2026, but a proceedings record was not available at the 2026-10-02 literature cutoff; we therefore label it accepted ,not formally published. It is the closest plan-verification comparison because it reasons about the whole proposed plan rather than an isolated tool call. Our evaluation therefore distinguishes initial plan verification from authorization of graph changes introduced after execution has begun, including invalidation and reauthorization after relevant version changes. The remaining closest works were preprints at the cutoff. Agent-C constrains tool-call generation using temporal specifications and SMT solving [24]; VIGIL checks order, parameter relations, and value flow across agent–tool events [30]. RGE monitors role, goal, and evidence drift at trajectory prefixes [21]. Agent Behavioral Contracts covers preconditions, invariants, governance policies, and recovery [10], while Structural Enforcement of Goal Integrity separates policy, authorization, and execution and tracks lineage [44]. Their publication status limits the weight of their reported empirical results, but their mechanisms still constrain our novelty language: temporal enforcement, drift monitoring, contracts, architectural separation, and lineage are not claimed as new.

5 Runtime Authorization Protocol 

The protocol places an authorization boundary between goal-graph mutation and effect execution. It does not prescribe how a planner generates goals. It requires the planner to expose each security-relevant mutation in a typed form that can be checked against the current root task contract. Figure 2 separates the two decisions. A graph mutation must be authorized before it becomes active; a later protected call must still match the current witness and versions at the commit boundary. Neither a planner-produced explanation nor an earlier allow decision bypasses the second check. 

5.1 Objects and identifiers 

Every root task receives a unique rootId , an immutable contract digest, and monoton-ically increasing policy and state versions. Each goal has a unique goalId , exactly one parent except for the root, a root identifier, a goal-local version, and a lifecycle state 

{active , closed , cancelled , replaced , joined }. A proposal is a request, not a persisted goal state. The root separately moves among active , suspended , and closed ; a version change suspends the root and stales witnesses rather than rewriting each goal as “invalidated.” A transition witness binds all fields used by the decision: parent and proposed goal digests, current committed trace digest, state and policy versions, the checker profile, and the decision. An effect request binds an idempotency key, active goal identifier, root identifier, normalized effect, expected trace digest, and the witness that made the effect reachable. A receipt binds the request to one outcome and, for a successful commit, to the new trace and state digests. Reusing an idempotency key with a different request body is rejected.

5.3 Effect reservation and commit 

Effect execution uses a two-step interface. authorizeEffect verifies the current goal and versions, normalizes the requested operation, advances a candidate residual state, and creates a single-use, context-bound reservation. The adapter may commit only the exact reserved normalized effect. On success, commitEffect appends the effect, records the observed state transition, updates the residual continuation system, and consumes the reservation at one linearization point. A failed 16 Zhu and Wang 

external operation records failure without claiming a successful state transition; any recovery goal is separately authorized. The separation makes races explicit. A policy or relevant state-version change invalidates outstanding reservations and transition witnesses before a later effect can commit. An exact retry returns the retained receipt. A conflicting retry under the same identifier is denied. These rules bind planner-visible goal evolution to operation-time enforcement rather than to a one-time plan approval. 

5.4 Delegation, joins, and replanning 

Delegation in this profile changes the executing worker, not the authorization root. The delegated goal must be an attenuation of its parent, and the worker receives only the active goal identifier and the fields required to construct valid requests. Worker-provided text is never an authority source. A same-root join names the complete sibling set, a permitted partial order, and the residual completion. The reference checker enumerates registered interleavings and verifies their prefixes. A new sibling cannot be added to an existing witness; the composition is rechecked and a new witness is issued. Cross-root joins are rejected in this paper’s profile. Replanning uses replaceGoal . The replacement is checked against the parent’s current residual language after the already committed prefix, not against the parent’s original start state. Thus a recovery plan can change method while preserving the task, but it cannot regain resources, erase an obligation, or make an already-forbidden state reachable. Cancellation is a tombstone, not completion evidence. It removes the cancelled node’s future effects and stales its witness, but cannot by itself justify closing the root. Recovery is explicit: 

replaceGoal may target the cancelled node, must pass the complete current-version transition check, and leaves the old node marked replaced. The replacement then follows the ordinary effect and closure rules. 

5.5 Receipts and auditability 

All accepted and rejected operations produce canonical, hash-linked records. The record contains typed inputs, version identifiers, the checker decision, and a reason code; it excludes private chain-of-thought. The independent checker consumes only the root contract, initial state, registered operation semantics, and receipts. It reconstructs the graph, trace, versions, obligations, and decisions without importing the runtime checker. This design turns auditability into a second implementation path rather than a copy of the same decision function. 

5.6 Fail-closed behavior 

Unknown schema fields, missing state observations, unsupported predicates, unbounded contin-uation systems, stale versions, and abstraction ambiguity do not authorize effects. They yield Indeterminate or Reauthorize with a typed reason. A deployment may seek a more precise abstraction or obtain principal approval; it may not silently treat uncertainty as authority.

7 Evaluation Design 

The evaluation separates seven evidence classes: (1) a minimal separating counterexample; (2) bounded exploration of the formal transition system; (3) conformance, mutation, and independent-checker tests; (4) controlled matched workflows; (5) structural mappings to frozen public task sources; and (6) calls through two frozen public tool-execution implementations; and (7) a secondary finite-envelope sensitivity study. Evidence is not pooled across these classes. In particular, a public-source mapping is not reported as execution of that benchmark, and bounded exploration is not reported as a proof of an unbounded theorem. The scale cells are not counted as external-source or upstream-runtime evidence.

9 Discussion 9.1 Authorization follows planning state 

The central systems implication is that goal-graph mutation is security relevant when it changes the effects that may become reachable. A planner may freely explore internal alternatives, but activating a child, replacement, delegation, or join is comparable to changing an authorization-relevant config-uration. Exposing that boundary permits conventional security techniques—reference monitoring, version checks, append-only receipts, and fail-closed decisions—to govern long-horizon behavior without attempting to police private reasoning text. This separation also clarifies the role of model alignment. An aligned planner can reduce the frequency of invalid proposals and improve recovery from a denial. The external mechanism supplies a different property: for the registered effect and state domain, protected operations cannot rely solely on the planner’s own assertion that a new subgoal is faithful. 

9.2 Relationship to plan verification 

Whole-plan verification and transition authorization are complementary. A complete finite plan can be checked before execution. Long-horizon agents, however, often change the plan after observations, failure, or delegation. Rechecking the complete model after every change is a strong baseline and may be the right implementation for small graphs. Incremental transition checks become useful when the retained witness identifies which residual language, invariants, and obligations are affected. The security property is the same: no graph update or effect commits without a current proof. The paper’s contribution is the authorization protocol and invariant, not a claim that incrementality is universally faster. Runtime Authorization of Self-Generated Subgoals 27 

9.3 Deployment patterns 

Coding agents provide one direct application. A debugging task may authorize repository reads, a test edit, and execution in a sandbox, while deployment, credential changes, and production traffic remain outside the root contract. A generated remediation subgoal can change method without acquiring those effects. Administrative agents can similarly rebook or refund within one customer, amount, and time window while preventing a recovery branch from widening the account scope. Data-analysis agents can revise statistical methods while retaining dataset, purpose, retention, and disclosure constraints. Manager–worker systems can delegate within one root task without allowing a worker’s summary to become a new source of authority. In each setting, the practical requirement is a typed operation and state boundary. Existing API gateways, transaction services, CI/CD controllers, or tool brokers can host that boundary. The agent runtime needs only to expose goal mutations and carry witness identifiers with protected calls. 

9.4 Abstraction and operator choices 

Exact finite reachability is not always practical. A deployment can use sound abstraction, bounded resource domains, conservative effect summaries, or domain-specific solvers. Coarser abstrac-tions tend to increase Indeterminate decisions rather than unsafe allows, provided the over-approximation and universal allow rule are preserved. The retained counterexample path helps operators refine only the state components that made a safe proposal ambiguous. Operators also choose what changes require principal reauthorization. A policy version advance, a resource-owner change, or a newly observed state may invalidate a witness immediately. Purely observational changes can remain outside the relevant version set. That dependency is declared in the root contract and tested by freshness mutants; it is not inferred from an agent’s description after the fact. 

9.5 Security composition 

Goal-transition authorization does not replace caller authentication, credential isolation, provenance tracking, input sanitization, rate limits, or settlement protocols. It consumes authenticated identities and trusted state versions, and it assumes the commit adapter is the only path to protected effects. In return, it supplies a composition property those controls do not individually provide: the current goal graph and its still-reachable effects remain inside one approved structured root task. 

10 Validity Conditions and Scope 

Construct validity. The primary outcomes are defined over registered state predicates, normalized effects, and trace membership. They measure authorization within that model, not every harmful real-world consequence. Matched benign and drifted cases hold the prefix and affordances constant to isolate goal evolution, while the independent checker prevents the runtime implementation from serving as its own oracle. 

Internal validity. Expected outcomes, workflow pairs, baseline inputs, mutation operators, and analysis rules are frozen before the final controlled execution. Each run records its initial and final state, complete receipt chain, adapter and contract digests, and reset result. Disagreement between validators blocks the result rather than being resolved by a subjective tie-breaker. Each comparison receives the precise input projection stated in Section 7. The strongest trace comparison receives the root trace policy, effect catalog and transition semantics, forbidden and required-terminal predicates, current state, complete committed prefix, complete proposed continuation, and proposed goal success predicate, and it blocks on unknown outcomes; it does not receive the typed lineage, 28 Zhu and Wang 

obligation, resource, version, or explicit join-evidence checks that define the distinct question under study. 

External validity. The study covers four operational domains, one separate access-grant join fixture, and two public tool-execution paths, with at least half of the workflow templates rooted in public sources. These are deliberately heterogeneous but do not represent every agent framework, enterprise policy, or physical environment. Claims are stated for the registered task families and finite contract profile. The adapter evidence tests the upstream dispatch and call paths; it is not evidence of deployment inside the upstream projects or endorsement by their authors. The study evaluates enforcement after a typed mutation is presented; proposal frequency and planning quality are separate outcomes. 

Scale-study validity. The secondary study is a single-host, one-factor-at-a-time characterization of synthetic deterministic fixtures. It does not estimate interactions among dimensions, production throughput, concurrent or distributed behavior, end-to-end agent latency, or performance on unseen contracts. Setup and fixture construction are excluded from decision latency. The five block medians are repeated process blocks on one machine, not independent machines or population replications, and no confidence interval or significance claim is made. A successful boundary cell establishes behavior at that registered input, not a recommended sustained operating capacity; fail-closed behavior is established only for the fixed cells. Each cell uses one isolated memory subprocess. The reported process.memoryUsage() values are pre-decision, immediate post-decision, and post-garbage-collection snapshots; their differences may be negative and are not peak-allocation estimates. process.resourceUsage().maxRSS is a process-lifetime high-water indicator that includes runtime and fixture setup, not memory attributable solely to the authorization call. Neither measure is portable across hosts or runtimes. 

Formal validity. The safety theorem depends on sound transition semantics, a sound over-approximation of future traces, fresh relevant versions, complete mediation, and a faithful commit adapter. The implementation-to-model table and targeted mutants exercise these premises sepa-rately. Bounded exploration supports the finite instances and finds counterexamples to weakened variants; it does not replace the mathematical proof. The finite decision property holds only where reachability is exact and all typed constraints are decidable in the registered domain. 

Structured-policy boundary. The mechanism starts from a principal-approved structured root task. It does not decide whether arbitrary natural-language goals entail one another and does not infer permission from free-form agent explanations. A deployment may use a model to propose the initial contract, but authority begins only after a trusted approval step. This is an interface boundary rather than an empirical assumption hidden in the evaluation. 

Single-root profile. Delegation and joins remain under one principal and one authorization root. Combining independent roots introduces principal conflict, authority algebra, and cross-root accountability that require a separate model. The checker rejects such composition instead of presenting an unproved rule. 

Availability and progress. Fail-closed behavior permits denial of service through repeated invalid or ambiguous proposals. Conditional success preservation establishes what is true when the root closes; it does not promise that a planner will find a valid plan or terminate. The evaluation measures benign completion and recovery so that this availability cost remains visible. 

Unmediated and irreversible effects. An effect outside the registered adapter is outside the protected execution. Likewise, invalidating a witness prevents future commits but cannot reverse an already Runtime Authorization of Self-Generated Subgoals 29 

completed physical action. Deployment therefore requires coverage analysis for effect paths and domain-specific compensation where reversal is needed. 

11 Conclusion 

Long-horizon tool use makes goal evolution part of the authorization state. Checking each call against a static permission set cannot enforce policies that depend on ordered composition, out-standing obligations, explicitly joined sibling interactions, or changed state. This paper makes goal creation, replacement, same-root delegation, and same-root joining explicit authorization events. A proposed transition is activated only when its structured continuation refines the current root task contract, and every protected effect is mediated against the resulting residual permitted trace language. The formal result establishes root-policy safety under explicit, testable assumptions and preserves required terminal predicates when the authorized goal graph closes. The artifact connects these results to bounded exploration, an independent checker, targeted mutants, six explicitly specified comparison mechanisms, paired external-source workflows, and two public tool-execution call paths. A separately frozen 129-cell sensitivity study additionally confirms the declared direct and internal finite-profile boundaries and makes their host-local cost curves explicit without converting them into a production capacity claim. Together, these elements provide a planner-independent method for allowing useful replanning and delegation without letting self-generated subgoals become a source of new authority within the registered structured domain and mediation assumptions.

B Registered Experimental Details B.1 Case schema 

Each workflow record contains: a globally unique case identifier; source family and source task identifier; license and immutable source reference; root contract digest; initial typed state; identical prefix; benign and drifted goal updates; ordered or partially ordered candidate effects; expected transition, commit, and terminal-state outcomes; drift class; relevant policy/state versions; and deterministic reset instructions. The schema rejects unknown security-relevant fields and requires every expected outcome to be derivable from the registered state/effect semantics. 

B.2 Baseline interface 

All controls replay the same ordered case definition from a fresh local state, but each receives only the projection that defines that control. The memoryless allowlist receives the normalized effect and root effect catalog; the static goal-effect control additionally receives the proposed goal’s resources and declared effects; the declared-purpose control also binds the current effect to that goal. The final-state control receives the resulting state and completed trace only after execution. The history-aware complete-continuation trace control receives the root trace language, effect catalog and transition semantics, forbidden and required-terminal predicates, current typed state, complete committed prefix, proposed completion traces, and proposed goal success predicate. The complete mechanism alone receives typed lineage, obligations, versions, resources, graph revisions, and transition witnesses. This design compares specified control classes rather than claiming identical information or a reimplementation of each cited system. 

B.3 Run retention 

A run contributes a policy outcome only when the case and runtime versions match the frozen registry, reset succeeds, all expected records are present, receipt hashes and denominators verify, and both validators agree. A crash, malformed runtime output, version mismatch, reset failure, or validator disagreement fails the evidence gate and receives no inferred policy outcome; none occurred in the frozen run. 

B.4 Mutation categories 

The registered mutation set covers the trusted premises represented in the implementation: effect mediation; root, parent, and worker identity; trace order and multiplicity; resource scope; success and forbidden predicates; active frame predicates; inherited obligations; residual completion; policy and state versions; same-root composition; reservation-to-commit binding; and idempotency. Each mutant has a minimal retained counterexample and an expected rejection reason. Mutants that merely corrupt an outer hash do not count toward semantic mutation coverage. 

B.5 Result generation 

All manuscript counts and percentages are produced from verified JSON result bundles. The generator checks the registered denominators, emits LaTeX macros and tables, and records a digest over its inputs. The manuscript build fails when a generated file is stale. Descriptive latency percentiles are derived from monotonic-clock measurements after correctness gates pass; they are not used to replace a failed security or utility gate.
