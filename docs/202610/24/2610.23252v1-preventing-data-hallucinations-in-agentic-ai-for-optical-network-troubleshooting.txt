# Preventing Data Hallucinations in Agentic AI for Optical Network Troubleshooting 

Jeremias Dötterl (1) , Martin Kuipers (2) (1) Adtran GmbH, Hermann-Dorner-Allee 91, 12489 Berlin, Germany, jeremias.doetterl@adtran.com  

> (2)

Adtran Networks SE, Hermann-Dorner-Allee 91, 12489 Berlin, Germany, martin.kuipers@adtran.com 

Abstract An agentic AI system for automated troubleshooting in optical communication networks is demonstrated that integrates data references into the agent architecture to prevent data hallucinations, improving the interpretability and trustworthiness of root-cause identification and reasoning. ©2026 The Author(s) 

Overview 

Service providers have a strong interest in au-tomating root cause analysis (RCA) in Passive Op-tical Networks (PON) to minimize the impact of ser-vice degradations and outages. Root cause mod-els for PONs analyze telemetry acquired from the equipment, such as Optical Line Terminals (OLTs) and Optical Network Units (ONUs), and predict probable causes, such as fiber bends, loose or dirty fibers, laser aging, power outages, or rogue ONUs. For use in real deployments, these models must be accurate and explainable to ensure relia-bility and operational trust. Only if the claimed root cause is sufficiently justified by the data, operators can trust the inference and confidently resolve the issue with appropriate remedies. Through recent advances in large language models (LLMs) [1], AI agents [2] have become capable of advanced language understanding and sophisticated reasoning. Therefore, AI agents are a promising paradigm for automating the trou-bleshooting and root cause inference in optical networks to an unprecedented degree. In a typi-cal setup, the agent is given access to the PON telemetry, a knowledge base, and a set of tools, and is instructed via a prompt to analyze the PON telemetry and infer the most likely root cause. How-ever, while today’s LLM-based agents are use-ful tools for assisting human experts in ad-hoc root cause analysis, their black-box nature [3, 4] and hallucinations [5, 6] prevent the adoption for wide deployments in commercial networks, where operators expect explainable inference and inter-pretable root cause claims. One of the major challenges with today’s AI agents is the risk of data hallucinations . Agents regularly generate responses that appear plausi-ble but contain incorrect information [6]. By de-fault, agent responses consist of raw text, in which the agent outlines its root cause claims and (if prompted to do so) the reasoning chain that sub-stantiates this claim. However, these textual re-sponses lack sufficient rigor that would allow op-erators to trust these responses. Whenever the agent makes a statement about the underlying PON telemetry, there is a risk that the agent hallu-cinates data, i.e., it refers to data in its responses that is not present in the actual PON telemetry. This makes standard AI agents unreliable and un-trustworthy for troubleshooting commercial PONs. In this demonstration, we present a new evidence-based framework for agentic network troubleshooting, in which the agent uses data ref-erences to point to data fragments in the PON telemetry. Using data references, the agent can cite specific subsets of the data in its claims and reasoning justifications, for example a spike or drop in a particular metric in a particular time win-dow. We show how data references can be inte-grated into the agentic AI architecture and demon-strate their benefits in various degradation and fault scenarios on commercial PON equipment. 

Novelty 

Currently, there is great interest in agentic AI meth-ods for the monitoring, configuration and fault man-agement of (optical) communication networks [7– 10] driven by fast progress in LLMs and agentic AI research. Our demonstration is aligned with these developments and enhances the current agentic AI architecture. The problem of hallucinations and low reliability of agentic AI (and generative AI more broadly) is a major challenge [9] that must be ad-dressed. The major novelty of the presented approach is the introduction of data references into the stan-dard agentic AI architecture to enable evidence-based root cause analysis in optical networks. Agentic consumer applications, like ChatGPT, use citations to link to information found on a web site. Data references in our architecture serve a sim-ilar purpose, but they link to data sources and are tailored to the requirements in optical network troubleshooting. Specifically, data references are designed to work with common telemetry data for-mats, such as time series data, log files, and struc-tured JSON. In our implementation, data references are stored as URIs where param-eters are used to encode information about the OLT, ONU, metric, time window, etc. Fig. 1 shows the Agentic AI for Optical Network Troubleshooting and its interaction with external systems and actors. The networks under obser-vation are PONs that are monitored by a data collector. Via the OLT, the data collector acquires telemetry that provides insights into the state and performance of the optical network, including traf-fic counters, bit-interleaved-parity (BIP) error coun-ters, TX/RX power levels, as well as detailed alarm logs. The networks can suffer impairments caused by fiber bends, loose connectors, sudden power outages, etc., whose diagnosis is time-consuming and costly in large installations. Whenever the service quality degrades, the operator can start a chat-based interaction with the agent to trigger the data collection and diagnosis process. The data collector takes a snapshot of the recent OLT telemetry and uploads it to the data lake in the cloud. This case data serves as the input data for the agent’s diagnosis. In a first analysis step, anomaly detectors 

process the case data and identify anomalous data that deviates from expected data patterns. These anomaly detectors can be implemented with heuristic rules or machine learning models. Their purpose is to inject domain knowledge into the RCA process and to steer the agent’s attention towards interesting data sections. While this com-ponent is optional, it can help reduce the agent’s token consumption and costs. The anomaly de-tectors use data references to point to the data fragments where the anomaly was found. The data references are written to a file system, where they can be inspected by the agent with standard tools like ls, grep, and read_file. The agent uses an LLM by an external provider 

for analysis and reasoning. Guided by the system prompt, the agent inspects the data references in the file system. Additionally, the agent is equipped with data inspection tools that allow the agent to run data queries. For example, the agent may use a tool to identify the temporal overlap of two anomalies, or to compute the correlation between two performance metrics. One important technical innovation in this archi-tecture is the enrichment of the agent–tool API contract: All data inspection tools include data ref-erences in their responses. This way, as the agent gathers information about the case data, it keeps track of the data locations. When the agent generates its answer, it is not allowed to generate a copy of the data in its re-sponse, as this poses a risk of data hallucination. Instead, the agent is instructed via the prompt to use data references to substantiate its claims. Fig. 2 shows an example: The time series of BIP errors of each ONU is stored in a data frame. If the agent wants to refer to an observed spike in the BIP error metric of ONU onu-345 at OLT olt-012 , it must include the correct data reference into its response. We have developed an evidence query API that accepts data refer-ences and extracts the correct data fragments from the original case data. This enforcement mecha-nism guaranties that all the data that are displayed in the enriched response exist in the case data. If the agent hallucinated data references (which we have not observed in our experiments), the evidence lookup would fail, and a warning would be displayed to the user. Finally, the enriched re-sponse is sent to the user interface where it is displayed to the user. 

ECOC Relevance 

Our demonstration contributes to the ECOC Demo Zone topic of AI/ML for network intelligence . The application of LLMs and agentic AI to optical net-works is an emerging and rapidly evolving re-search area of significant relevance to the ECOC community. At the same time, data hallucinations remain a major obstacle to the adoption of AI agents in operational networks, where incorrect decisions can have substantial operational and economic impact. Consequently, improving the robustness, reliability, interpretability, and trustwor-thiness of AI agents is a critical requirement for delegating operational decisions to such systems. In this context, our demonstration presents a novel integration of LLM-based agent systems and data references for optical network monitoring and trou-bleshooting. The demo illustrates how combining the adaptability of modern AI agents with the ex-plainability provided by data references can enable more trustworthy and resilient network operations. As such, the work is relevant to both researchers and network operators attending ECOC. 

Demonstration Content and Implementation 

The objective of the demo is to demonstrate how an agentic AI system for troubleshooting optical network issues can be made reliable and trust-worthy. In particular, the demo illustrates how the proposed data-reference approach prevents data hallucinations, thereby improving the interpretabil-ity and trustworthiness of the root-cause claims generated by the agent. The agentic AI system is implemented as a Python application using the deepagents 1 library by LangChain to realize the agent harness. The agent operates in a reasoning loop in which it is guided by a prompt and invokes tools as needed. Specialized tools were implemented that allow the agent to inspect the case data. Both anomaly detectors and data inspection tools include data references in their responses. Rendering functions were implemented to visualize these references with plots and quotes from the underlying teleme-try data. Most commercially available LLMs can be used within the system through LangChain’s integrations with common model providers. The demo involves multiple lab installations at Adtran premises, consisting of OLTs and multi-ple ONUs. Similar to the techniques used by [11, 12], representative faults will be provoked on these installations, including distribution fiber cuts, feeder fiber cuts, and sudden ONU power outages. Through the data collector, the agentic system ac-quires live telemetry data from these installations. This setup enables the demonstration of different failure modes and provides diverse troubleshoot-ing scenarios. Attendees will interact with the system through the web-based user interface. They will be able to engage with the agent in multi-turn conversations. The agent performs root-cause analysis (RCA) on live telemetry data and uses data references to point to relevant fragments of the underlying data. The user interface visualizes the referenced PON telemetry through plots and quotes. By con-trasting this evidence-based implementation with an agentic analysis approach that does not use data references, the advantages of the proposed method for interpretability and trustworthiness are highlighted.
