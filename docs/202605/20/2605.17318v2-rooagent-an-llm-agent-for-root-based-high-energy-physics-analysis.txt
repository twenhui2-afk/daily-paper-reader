Abstract 

We present RooAgent as a natural-language interface for Root -based high energy physics data analysis. The package provides physics analysis functions as tools that an LLM agent invokes in response to plain-language prompts. Two operating modes are supported: a LangGraph -based agent compatible with OpenAI ’s GPT-4.1 via GitHub Copilot and with DeepSeek-V3 via Ollama ,and a Model Context Protocol server for use with the Anthropic Claude CLI ( Sonnet 4.6 ). In both modes the analysis logic is implemented in PyRoot and the LLM selects tools and supplies the required arguments. The package supports histogram inspection, event selection, visualisation of kinematic distributions, fitting, and significance estimation, among other tasks. We illustrate 

RooAgent with tests based on Monte Carlo simulations of pp → ZH (Z → ℓ+ℓ−, H → b¯b), a multi-task signal-background workflow, a toy statistical analysis, and an application to ATLAS open data for H → ZZ ∗ → 4ℓ. The package is available on PyPI and the source code is hosted at 

https://github.com/amanmdesai/RooAgent .

# 1 Introduction 

High Energy Physics (HEP) data analysis relies on the Root framework [1] for tasks such as event selection, histogram preparation, and statistical inference in collider physics studies. Root and its Python interface PyRoot [2] provide a flexible toolkit, but working with them requires familiarity with their API conventions 1 and the structure of each input sample. A natural-language interface that maps plain-language goals to Root function calls can benefit new users and streamline routine tasks. Large language models (LLMs) [3] can invoke external functions through the so-called ‘tool calls’ [4, 5], enabling multi-step HEP workflows from natural-language prompts. Machine learning has been widely used in HEP data analysis [6–10], and LLM-based agents for tasks such as event selection, histogram production, statistical inference, and result interpretation [11–24], and automated event generation [25], among other aspects have been actively studied. 

RooAgent [26] provides a library of analysis tools invoked by an LLM agent. The package wraps 

PyRoot [2] functions as tools. The LLM interprets the user’s input, selects the appropriate tools, and supplies the required arguments, while Root performs the computation. The package supports two operating modes: a LangGraph [27] based agent for use with the OpenAI [28, 29] or Ollama [30] APIs and a Model Context Protocol (MCP) [31] server for use with the Claude CLI [32]. In both modes the

# 2 RooAgent Software 

RooAgent is written in Python and supports two operating modes: a LangGraph -based agent mode for use with OpenAI or Ollama models and a Model Context Protocol (MCP) server mode for use with 

Claude CLI. Both modes expose the same underlying Root analysis tools, implemented in PyRoot [2]. In both cases, Root [1] must be installed separately. 

## 2.1 LangGraph Agent Mode 

In this mode, the LLM reasons over user prompts, selects tools, constructs arguments, and calls PyRoot 

functions iteratively until the goal is met. Installation is via PyPI 2:

> pip install rooagent

or from source: 

> git clone https://github.com/amanmdesai/RooAgent.git cd RooAgent pip install .

The additional required Python packages are: 

• langchain [33], langchain-core , langgraph [27] 

• either langchain-openai or langchain-ollama [34] 

• pandas [35], numpy [36], scipy [37], matplotlib [38] By default, the package uses OpenAI ’s GPT-4.1 model [28] accessed via GitHub Copilot’s API [29]. Runtime behaviour is controlled through the following environment variables: 

• GITHUB_TOKEN : authentication token for model access. 

• MODEL (optional): model identifier. Default is openai/gpt-4.1 .

• ROOAGENT_SEED (optional): random seed for reproducibility. Default is 7.To use locally hosted models, switch to the Ollama branch:  

> 2PyPI version of the software supports access to LLMs via GitHub models only.

2git clone https://github.com/amanmdesai/RooAgent.git cd RooAgent git checkout ollama_models pip install . 

This configures LangGraph [27] to use the DeepSeek-V3 model [39] via Ollama [30]. Any other locally installed Ollama model can also be used by configuring MODEL parameter in the terminal. The tool set is identical across both backends. The system’s prompt is stored in agent.py .

## 2.2 Model Context Protocol Mode 

RooAgent can also run as an MCP server integrated with the Claude CLI [31]. Here, Claude acts as both the LLM and orchestration layer, with no LangChain or LangGraph installation required. The MCP variant is available on the claude_models branch and can be installed using the following commands: 

> git clone https://github.com/amanmdesai/RooAgent.git cd RooAgent git checkout claude_models pip install .

Additional required packages for this mode: 

• fastmcp [40]: the FastMCP library used to implement the MCP server 

• pandas [35], numpy [36], scipy [37], matplotlib [38] After installation, register the server once with the Claude CLI: 

> claude mcp add rooagent --rooagent-mcp

To run an analysis, navigate to the directory containing the Root files and launch Claude :

> cd /path/to/your/root/files claude

The repository’s CLAUDE.md is read automatically at the start of Claude session and it carries the system’s prompt — including available tools, recommended workflows, default parameters, and analysis rules — so no additional configuration is needed. The model chosen as default is the one configured in the user’s Claude settings. For tests here, we used Sonnet 4.6 [32].

# 3 Results with RooAgent 

We evaluate RooAgent on Monte Carlo simulated samples. In each benchmark test, the user provides a natural-language prompt. The LLM selects the appropriate tools, infers the required arguments, and produces the final output without human intervention. 

## 3.1 Monte Carlo Sample 

Development and testing used two Monte Carlo samples. The signal sample corresponds to pp → Z(→

ℓ+ℓ−)H(→ b¯b); a representative leading-order diagram is shown in Figure 2. The background sample is the continuum process pp → ℓ+ℓ−b¯b, with the same visible final state but no intermediate Higgs bo-son. We simulated 500 000 events for each process using MadGraph5_aMC@NLO [43] at the LHC Run 3 centre-of-mass energy of √s = 13 .6 TeV. The PDF4LHC21 PDF set [44] was used, accessed via 

Lhapdf6 [45]. The hard-scatter events then passed via Pythia8 [46] to incorporate effects of parton shower and hadronisation. The resulting hadrons were clustered into jets with FastJet [47] via the 

MadAnalysis5 [48] interface, using the anti-kT algorithm [49] with R = 0 .4. The MadAnalysis5 out-put in the LHE format [50] was processed with the LHEReader [51] and an EventLoop function [51] to produce a Root file with a TTree of kinematic branches and pre-filled TH1D histograms. 5q

The EventLoop function applies object selection and reconstructs composite final states from four-momenta. Electrons, muons, and jets are required to satisfy pT > 25 GeV and |η| < 2.5. A lepton–jet isolation requirement ∆R(ℓ, j ) > 0.4 is imposed. The dilepton invariant mass is required to satisfy 

mℓℓ ∈ (76 , 106) GeV, consistent with an on-shell Z boson. b-jets are identified using generator-level particle flavour information. Each event carries a weight combining the process cross-section, generator weight, and a fixed normalisation factor, used throughout to produce yields at a defined integrated luminosity. In the following, all output boxes (“Final Answer”) were generated entirely by LLMs. Human involvement was limited to writing the input prompt. Final results were post-processed by Claude (Sonnet 4.6 )3,e.g. fixing latex issues or merging multiple samples’ cutflows. No further review was applied beyond the tools’ internal checks. All tests used GPT-4.1 [28] via GitHub Copilot [29], unless stated otherwise. Qualitatively, similar results were obtained with DeepSeek-V3 [39] via Ollama [30].

# 4 Statistical Analysis with RooAgent 

To test the statistical tools, we constructed a toy invariant mass spectrum with a smoothly falling exponential background and Gaussian signal templates at several mass hypotheses 5. The observed data contain background plus a signal contribution injected at 250 GeV, giving an expected excess localised at that mass. Smaller contributions of signal were also injected at 100 and 400 GeV. The toy dataset is stored as histograms in DataSample_search.root , one per observable per mass hypothesis on a grid from 100 to 500 GeV. For each mass point, the agent integrates the histograms in a ±25 GeV window and computes: 

• the observed significance Zobs and corresponding p-value, based on the actual observed counts, 

• the expected significance Zexp and p-value, computed from the Asimov dataset under the signal-plus-background hypothesis, 

• the CL s value for the signal-plus-background hypothesis at each mass point, using the asymptotic formulae of [53]. The prompt and response below illustrate the analysis, with plots shown in Figure 16.

# 5 Analysing Open Data with RooAgent 

As a final example, we apply RooAgent to open data: the H → ZZ ∗ → 4ℓ search using ATLAS open data [54–56]. This dataset is publicly available for educational use, and also included in HEP Software Foundation (HSF) Training Working Group exercises on matplotlib visualisation [57]. The open dataset is a subset (10 fb −1)of the ATLAS Run 2 dataset collected at √s = 13 TeV. The analysis targets the 20 four-lepton final state in three channels ( 4e, 2e2μ, 4μ), applying lepton selection cuts before comparing MC predictions to data in the four-lepton invariant mass m4ℓ.Momenta in this dataset are stored in MeV, so lepton pT thresholds are given as 25 000, 15 000, and 10 000 (i.e. 25, 15, and 10 GeV). Lepton flavour combinations are encoded in goodlep_sumtypes : values 44 ( = 4 × 11 ), 48 ( = 2 × 11 + 2 × 13 ), and 52 ( = 4 × 13 ) select 4e, 2e2μ, and 4μ using PDG codes 11 (electron) and 13 (muon). These are stated explicitly in the prompt so the agent can construct the correct selection expressions. The ATLAS open data files use a sum_ prefix for event-level multiplicity branches (e.g. sum_good_lep ); the agent tended to interpret this as a summation instruction rather than a scalar read. These branches were therefore renamed sum_* → N_* (giving N_good_lep and N_lep_charge ) in all five files using a pre-processing script. The prompt follows the educational tasks of Ref. [57].

# 6 Conclusions 

We presented RooAgent a natural-language interface that bridges plain-language prompts and Root -based HEP analysis through an LLM agent. The package supports two backends—a LangGraph -based agent compatible with OpenAI ’s GPT-4.1 [28] (via GitHub Copilot [29]) and DeepSeek-V3 [39] (via 

Ollama [30]), and an MCP server for the Anthropic Claude CLI [32]—while sharing the same PyRoot 

23 implementations across both, so switching models requires no changes to the analysis code. The benchmark tests demonstrated successful completion of a range of tasks, including file inspec-tion, histogram visualisation, event selection, kinematic comparisons, fitting, and significance estimation, across Monte Carlo simulations of pp → ZH (Z → ℓ+ℓ−, H → b¯b), a multi-task signal-background work-flow, a toy statistical analysis, and ATLAS open data for H → ZZ ∗ → 4ℓ. In all cases the LLM handled orchestration and argument selection while the PyRoot tools produced the numerical results. The tool set is modular and can be extended by registering new PyRoot functions. Natural direc-tions for future work include LLM-guided identification of optimal event-selection variables, integration of machine learning algorithms as callable tools, and validation on more complex, realistic analysis work-flows.
