Abstract 

Given an undirected weighted graph G, a γ-approximate low-stretch spanning tree (LSST) 

T ⊆ G is a tree that approximates the distance metric of G up to a γ-factor in expectation. Currently, existing algorithms to find a provably good LSST carefully construct an approximate shortest-path tree from an arbitrary source. The resulting algorithms are intricate. In con-trast, practitioners observed that a much simpler heuristic performs surprisingly well: choose an arbitrary root, run Dijkstra’s algorithm, and use the resulting shortest-path tree as an LSST. In this paper, we give a smoothed analysis of shortest-path tree algorithms, such as Dijkstra’s algorithm, that explains this behavior. We show that adding a small perturbation to the weights of the input graph suffices to turn the shortest path tree rooted at an arbitrary node in the resulting graph into an ˜O(1)-approximate LSST. We further show that the set of perturbations can be computed efficiently from few low-diameter decompositions (LDDs). Thus, our proof is also constructive in the sense of giving a novel approach to computing LSSTs.

Low-stretch spanning trees, and more broadly tree embeddings, are the cornerstone of a now-standard paradigm in graph algorithms: replace the input graph by a single tree that approximates its metric, on which cuts, flows, distances, and linear-algebraic primitives become more tractable and easier to reason about. Hence, low-stretch spanning trees and tree embeddings, as defined below, have been studied intensively over the past decades [AKPW95, Bar96, Bar98, FRT03, Bar04, EEST05, ABN08, AN12, FG19, CZ20, FGH21, REGH22, BEGL24, KPGR25, FH26]. 

Definition 1.1 (Low-Stretch Spanning Tree) . Given a weighted undirected graph G = ( V, E, w :

E → [W ]) , we say that a tree T ⊆ G drawn from some distribution T over spanning trees of G is a randomized γ-approximate low-stretch spanning tree if for every vertex pair u, v ∈ V ,

ET ∼T [dist T (u, v )] ≤ γ dist G(u, v ).

A tree embedding is defined analogously but without the restriction that the trees T have to be subgraphs of G.

Most notably, this paradigm underlies the first near-linear time solvers for Laplacian systems [ST04a, KMP14, KMP11, KOSZ13], where low-stretch spanning trees serve as preconditioners. More recently, it has also been a key ingredient in the first provably fast almost-linear-time algo-rithms for min-cost flow [CKL +25, VDBCK +23, CKL +24]. 

Low-Stretch Spanning Trees in Practice. In practice, LSSTs were first implemented and evaluated [HLMW15, DGM +16] as a primitive for practical Laplacian graph solvers. Very recently, they have been used in the implementation [SMKG26] of the min-cost flow solver from [CKL +25]. During their implementation, the authors of [SMKG26] made a curious observation. They noted that the often intricate algorithms for computing low-stretch trees are matched, and sometimes even outperformed, by a strikingly simple heuristic: run Dijkstra’s algorithm from an arbitrary vertex and use the resulting shortest-path tree as a low-stretch spanning tree. From the perspective of algorithm analysis, this observation is somewhat matched by the fact that existing polylogarithmic-stretch constructions can be viewed, at a high level, as carefully engineered approximate shortest-path trees grown from an arbitrary source (c.f. [EEST05, ABN08, AN12, FH26]). This gives an intuitive explanation for why such a phenomenon seems plausible in practice. On the other hand, simple examples show that the exact shortest-path tree from an arbitrary source can have very poor stretch. 

Beyond Worst-Case Analysis. Since worst-case analysis cannot fully explain the behavior seen in practice, the algorithm analysis community has introduced average-case analysis and smoothed analysis [ST04b]. While the former framework often lends an interesting perspective, as noted in [ST04b], it is often unconvincing to analyze performance over a random distribution of instances, as real-world instances are often highly structured and might thus look very different from the average input. Instead [ST04b] introduced smoothed analysis, which analyzes algorithmic performance under small perturbations to the input. More precisely, given the set of input instances I ∈ I and an appropriate definition of a small neighborhood N (I) for each instance, along with a distribution 1over the neighborhood, 1 it measures the expected cost of algorithm A evaluated on the small neighborhood of each instance max

Given any input graph G, can we apply a small perturbation to its weights so that thereafter any exact shortest-path tree from an arbitrary vertex is provably a good low-stretch spanning tree? 

Equivalently, we ask whether a smoothed analysis [ST04b] of Dijkstra’s algorithm for computing low-stretch spanning trees can recover the behavior observed in practice.

We remark that the inverse dependence of the algorithm performance on the size of the noise ε is intuitively to be expected and standard in smoothed analysis. One way to interpret Theorem 1.2 is that, viewing weighted graphs as points in RE , every graph is “close” to many graphs on which the SSSP tree is already well-behaved. The most natural approach is to consider i.i.d. sampling of the perturbation. However, we next demonstrate that sampling perturbations i.i.d. fails on the cycle graph Cn. Recall first, that on the cycle graph, any LSST is formed by removing a single edge e from Cn, which yields stretch n − 1for the removed edge. Consider the shortest path tree Tr from some arbitrary vertex r. On Cn, it omits the edge opposite to the root r. In order to recover eO(1) stretch for every edge, we need to redistribute the omitted edge over at least eΩ( n) edges with good probability. Now consider the case where perturbations are i.i.d. and bounded, i.e. each ∆( e) ∈ [0 , C ] for some universal constant C > 0. In this case, we can apply a Chernoff bound to get concentration of the distances in the perturbed graph, which yields that no vertex is at distance further than 

O(√n) from expected w.h.p. But this distributes the omitted edge only over eO(√n) edges opposite to r. Thus, on average, these edges are still left with eΩ( √n) stretch. Let us therefore assume that random variables ∆( e) are unbounded. However, consider now the graph where we replace each edge on Cn with α = 10 log n multi-edges (again of weight 1). Distance computations only consider the edge among the multi-edges with the smallest perturbation. But by Markov, any fixed edge e has perturbation at most 2 · E[∆( e)] = O(w(e)) with probability at least 1 /2. Consequently, one of the multi-edges thus has weight O(w(e)) w.h.p., and this is true for all original edges in Cn. Since we can condition on this event, we thus find ourselves again in the previous bad scenario. We conclude that i.i.d. sampling does not seem sensible to obtain the desired perturbations.
