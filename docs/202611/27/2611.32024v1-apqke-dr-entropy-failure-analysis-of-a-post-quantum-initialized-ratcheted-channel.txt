# APQKE-DR: Entropy-Failure Analysis of a Post-Quantum-Initialized Ratcheted Channel 

Muhammad Asfand Hafeez , Graduate Student Member, IEEE, Zain Ul Abideen , Member, IEEE, ,Amna Zafar ,Kazi Hassan Shakib , Member, IEEE , Arslan Munir , Senior Member, IEEE 

Abstract —Long-lived secure channels for embedded and cyber-physical systems (CPSs) must resist quantum attacks and failures in endpoint randomness. While several post-quantum key exchange protocols exist, their security assumes reliable randomness at the endpoint, but this assumption is not always true in embedded devices. In this paper, we introduce the Entropy Attack Suite (EAS) to evaluate secure channels facing endpoint randomness failures, such as low-entropy boot and Random Number Generation (RNG) path subversion. As a case study, we design and implement APQKE-DR, a post-quantum secure channel. Its handshake uses ML-KEM [1] and ML-DSA [2], producing a root key for an X25519 Double Ratchet. We assess APQKE-DR’s performance and security for smart grid communication, and integrate it beneath ANSI C12.22 and DNP3 without altering payload formats. On a Raspberry Pi Compute Module 5, the APQKE handshake exchanges 9,610 bytes with median latencies of 1.99 ms (node) and 0.82 ms (server). The ratcheted channel adds 31 bytes per message. With fresh randomness and ideal cryptographic primitives, ProVerif verifies the modeled secrecy and authentica-tion properties. If randomness fails, EAS can recover the RNG stream and root key from public transcripts. Under RNG-path subversion, a weak generator exposes the root key across sessions. If subversion also affects X25519 keys, attackers may access ratchet keys and plaintexts. TPM seeding prevents early-boot attacks but not later subversion, while measured boot can block modified firmware. Secure deployment thus requires integrity along the entire entropy path, not just strong cryptographic primitives. 

I. I NTRODUCTION 

Modern embedded and cyber-physical systems (CPSs) rely on continuous communication between field devices and central-ized control services, carrying measurements to control software and returning commands that drive system operation. Smart grids apply this model to electricity distribution: smart meters and other field devices send usage and grid measurements to supervisory control and data acquisition (SCADA) backends, which monitor conditions and coordinate control actions [3]– [5]. This connectivity improves visibility and automation but exposes devices and communication channels to attacks that can cause incorrect billing, falsified measurements, loss of visibility, or disruption of control functions [6]–[8]. In these systems, each connection has two endpoints : a field device and a backend server. These endpoints establish session keys to protect their communication, typically using

A sufficiently capable quantum adversary can break these public-key primitives and recover these keys, which would allow it to decrypt previously recorded traffic [10], [11]. Migrating away from these algorithms is difficult because field devices span a wide capability spectrum, from microcontroller unit (MCU)-class platforms to Linux-based gateways and the most resource-constrained devices in this range offer limited memory capacity and computational headroom. Post-quantum key exchange (PQKE) addresses the quantum threat, but it still requires unpredictable random inputs at the endpoints [12]. For a key-encapsulation mechanism (KEM), randomness is needed to generate an ephemeral keypair and to establish a shared secret using the recipient’s public key. An endpoint’s random number generator (RNG) can violate this requirement if it is initialized with too few unpredictable bits or if modified software replaces its output with a predictable sequence [13]. Suppose the device uses the same RNG stream for its random KEM inputs and its handshake nonce which is used to distinguish protocol runs. If the set of possible streams is small enough to enumerate, an attacker first regenerates the nonce for each stream and compares it with the recorded nonce. For each match, the attacker regenerates the device’s KEM keypair and encapsulation ciphertext. The regenerated public key and ciphertext are then compared with the recorded handshake messages. If both match, the attacker uses the regenerated private key and encapsulation randomness to recover the shared secrets. This search requires knowledge of the RNG algorithm and the order in which the protocol requests random values, but no further interaction with the device [14]. Fig. 1 illustrates the quantum threat and endpoint randomness failures in communication between a smart meter and a utility backend. Existing protocols provide an authenticated key establish-ment mechanism for updating encryption keys. Transport Layer Security (TLS) 1.3 authenticates its handshake transcript and confirms the derived keys, but its KeyUpdate mechanism derives each new traffic secret from the previous one. An attacker who obtains that secret can therefore derive subsequent traffic keys on the same connection [15]. The Signal protocol [16] addresses this limitation by incorporating fresh shared secrets through ratcheted messaging, including classical and post-quantum updates in its Triple Ratchet [17]. However, its post quantum (PQ) extended Diffie-Hellman (PQXDH) handshake still relies on classical elliptic-curve cryptography for mutual authentication [18]. Our contributions are as follows:  

> •

We design and implement APQKE-DR , an experimental secure channel for the smart grid node-to-server interface. The APQKE handshake provides authenticated post-quantum key establishment using ML-KEM for key encapsulation and ML-DSA for signatures [19], [20], binds the derived root key to an authenticated transcript hash, and applies explicit Finished-style key confirmation [14], [21]. > •

> •

Section V covers the security analysis and results. Finally, Section VI concludes the paper. II. B ACKGROUND , S YSTEM AND THREAT MODEL 

The smart grid connects resource-constrained field devices via heterogeneous links. Key establishment and authentication protocols in smart grids focus on minimizing computational, bandwidth, and energy costs at endpoints, often using elliptic-curve primitives such as ECDH/ECDSA, along with symmetric encryption and message authentication codes (MACs) [26]. A wide range of lightweight and Advanced Metering Infrastruc-ture (AMI) focused designs refine handshake structure, reduce state, and optimize message formats to fit metering and SCADA constraints [27], [28]. Motivated by “record now, decrypt later” threats and the susceptibility of RSA/ECC to quantum algorithms [10], [11], re-cent work has explored integrating PQ primitives into smart grid and AMI security architectures. Prototypes have investigated Kyber and FrodoKEM-like mechanisms and their feasibility for embedded AMI deployments [29], [30], while other proposals develop lattice-based mutual authentication and key exchange protocols designed for smart grid communication [31]. These studies demonstrate that PQ primitives can be engineered into metering infrastructures, but they predominantly focus on initial session establishment and system integration. End-to-end secure messaging over long-lived channels, including forward secrecy, post-compromise recovery, and robustness to realistic endpoint randomness failures, is less frequently discussed. Outside the smart grid literature, secure-channel protocols provide well-established patterns for transcript binding and explicit key confirmation, notably in TLS 1.3 (transcript hash and Finished) [14], [21], as well as modular handshake frameworks, such as noise [32]. For long-lived encrypted messaging, the Signal Double Ratchet is a widely deployed construction for forward secrecy and post-compromise recovery, with formal security analyses [33], [34]. Parallel work has also explored post-quantum directions for secure-messaging handshakes [35]. 

A. System and Threat Model 

Smart-grid nodes {SGN i} use encrypted APQKE-DR channels to communicate with the utility server S (Fig. 2). Field devices include smart meters, remote terminal units (RTUs), phasor measurement units (PMUs), and gateways. AMI concentrators relay ciphertext without access to channel keys. Field links may use home or neighborhood area networks, such as home area networks (HANs) and neighborhood area networks (NANs). Both field and backhaul links are untrusted: an attacker can observe, modify, or block messages. A trusted authority provisions each node with the server’s ML-DSA verification key and registers each node’s verification key at S. Handshakes do not contact the authority. Nodes may have a hardware entropy source or TPM. Software updates are signed, and legitimate ratchet-state loss after a reset requires a fresh APQKE handshake. We distinguish six adversaries:  

> •

Anet is an active Dolev-Yao network adversary that can observe, modify, inject, replay, reorder, delay, or drop messages; initiate concurrent sessions; and mount compu-tational or state-exhaustion denial-of-service attempts.  

> •

Aseed can reset or power-cycle SGN i, control handshake timing, and knows the modeled low-entropy boot-seed distribution but cannot read endpoint secrets. 3 

> •

Arng controls only the bytes returned by the node’s RNG application programming interface (API). It cannot access long-term keys, plaintext, ratchet state, TPM state, or other process memory.  

> •

Aimg can install and attempt to boot a modified image but cannot forge an approved measurement or bypass the enforced TPM PCR policy. An unauthorized image, therefore, causes the node to fail closed before channel establishment.  

> •

Astate temporarily obtains the current Double Ratchet state, including the current root and chain keys, but later loses access and does not obtain provisioned keys or future randomness.  

> •

AQ records network traffic today and gains access to a large-scale quantum computer in the future, without live endpoint compromise. We assume a trustworthy provisioning authority and ML-DSA keys, correct cryptographic implementations, secure erasure of ephemeral KEM secrets, and used message keys, enforcement of the TPM measured-boot policy, and integrity of persistent credentials and ratchet state. Legitimate state loss is allowed, but malicious rollback or cloning of persistent state is out of scope, as are arbitrary or ongoing runtime-memory compromise, invasive physical attacks, compromise of the trusted authority or TPM, and side-channel or fault attacks. The protocol does not aim to resist sustained flooding, total state exhaustion, or indefinite message dropping. 

AQ and Astate capture different goals. AQ addresses confi-dentiality of recorded sessions initialized through ML-KEM against future passive quantum adversaries. Astate addresses recovery after live ratchet-state compromise, which depends on a later uncompromised X25519 update and therefore offers only classical post-compromise recovery.

III. P ROPOSED PROTOCOLS 

In this section, we present our APQKE-DR protocol for secure communication between a provisioned embedded end-point SGN i and the utility backend server S. The design includes two parts: APQKE , which is an authenticated post-quantum handshake generating an initial root key ( RK 0) and an authenticated transcript hash ( T H 1), and the DR data channel, which is resource-aware, seeded by RK 0, and tied to the handshake using T H 1 for application traffic. To manage resources,We have implemented a resource-aware rekey schedule. APQKE is executed during the initial connec-tion, during state loss, and periodically thereafter. Meanwhile, the Diffie-Hellman (DH) ratchet refresh operates continuously with compact message headers. 

A. Trusted Authority (TA) assisted distribution of long-term ML-DSA keys 

We assume a trusted authority (TA) that distributes long-term ML-DSA public keys out-of-band before deployment. Unlike certificate-based PKI, the TA does not issue certificates or transmit certificate material during the handshake. Instead, the TA securely provisions the server’s long-term signature verification key to each device and vice versa. In concrete terms, the backend server has a long-term ML-DSA key pair (sk sig S , pk sig S ), and each node of the smart grid has (sk sig SGN i , pk sig SGN i ). During manufacturing, pk sig S is written in each SGN i (key pin), while the server stores 

(ID i, pk sig SGN i ) in a registration table indexed by device identity. This enables APQKE to authenticate all ephemeral ML-KEM keys by verifying signatures under pre-provisioned ML-DSA verification keys, without repeatedly transmitting any static public keys on the network. For compact on-wire identity representation, deployments may use a short key identifier, e.g., kid S = H(pk sig S ), kid i =

H(pk sig SGN i ), so that a receiver can select the correct pinned/reg-istered key with minimal overhead.

A. Early-boot Entropy Hole 

Smart-grid nodes may reset after outages, maintenance, or updates, creating an early-boot entropy risk if cryptographic operations begin before the endpoint DRBG/CSPRNG is securely initialized [22]. Whether this risk arises depends on the application’s randomness interface. On Linux, getrandom() 

with zero flags waits for RNG initialization, whereas direct reads from /dev/urandom may return output earlier [36]. Seeding an application-level generator from a timestamp can also leave its output predictable if an attacker knows or controls the approximate reset time [37]. The APQKE handshake protocol requires device-side ran-domness for the SGN nonce, ephemeral ML-KEM key gen-eration, and the encapsulation coins. Predictability in these inputs can expose the handshake root key RK 0. To evaluate this failure mode in a controlled way, we implemented an early-boot RNG mode at the entropy boundary (i.e., we intercept the seeding interface in Fig. 4). The weak-RNG interval is injected into the experimental platform 1 and does not represent a measured failure of its normal Linux RNG. B. RNG Path Subversion 

On the SGN, the handshake needs cryptographically secure random bytes to generate its nonce and ephemeral ML-KEM keys. These bytes come from the OS RNG API, ultimately seeded by a hardware entropy source. We refer to the chain from entropy source to OS generator to handshake code as the 

RNG path . The early-boot entropy hole is a transient fault at the start of this path: shortly after reset, the generator may be seeded with low entropy, making its output feasibly enumerable. RNG-path subversion is a persistent fault near the end of the path: compromised firmware or software intercepts or replaces RNG API outputs with attacker-predictable bytes, regardless of the true entropy source. RNG subversion is a well-established threat model, previously analyzed in the context of TLS implementations [38] and noted in the Double Ratchet specification [17]. Below describes how an adversary who controls the RNG API output recovers the root key RK 0

from a recorded handshake, and what this recovery implies for the confidentiality of later Double Ratchet message keys. Section V-D reports the experimental results, including the mitigation methods. In the reported experiment, the constrained attacker Arng 

controls only the returned random bytes. The upstream entropy sources, server RNG, provisioned keys, and other process memory remain uncompromised. The controlled APQKE retrieves are the SGN nonce NSGN i , ephemeral ML-KEM key-generation randomness, and encapsulation coins. A. ProVerif: Security Analysis 

We evaluated APQKE protocol in ProVerif [25] under the standard Dolev-Yao attacker that fully controls the network (intercept, modify, replay, and inject messages), while crypto-graphic primitives are modeled as ideal (perfect ML-DSA signa-tures, perfect ML-KEM encapsulation/decapsulation, collision-resistant hashing, and standard models for HKDF/MAC/AEAD). APQKE handshake ensures secure communication by authenti-cating the ephemeral ML-KEM key exchange using long-term ML-DSA verification keys and binds the entire handshake context to the hash of the transcript T H 1. The SGN accepts the server after confirming the server’s signature on T H 1

and verifying that the server’s message is complete. The server accepts the SGN only after verifying the encrypted finished message and then performing decapsulation. The key goal checked in ProVerif is secrecy of the derived RK 0

(and intermediate handshake secrets), where RK 0 is com-puted from both KEM shared secrets and is transcript-bound as RK 0 = HKDF( ss SGN i ∥ ss S , "dr-root" ∥ T H 1).ProVerif proves secrecy queries (the attacker cannot derive RK 0

or the KEM shared secrets) and authentication correspondence queries (whenever an entity reaches an accept event for T H 1,a matching peer begin event must have occurred with the same identities and transcript). In the symbolic model, these results rule out classic network attacks against the handshake, such as man-in-the-middle key substitution, replay-based transcript splicing, and impersonation without breaking ML-DSA/ML-KEM or forging the Finished MACs. Results: RNG path subversion (LCG): We have evaluated RNG-path subversion by interposing a malicious shim (i.e., an interposition layer that replaces RNG API outputs) at the SGN-side RNG API and forcing all device-side randomness con-sumed by APQKE protocol to be generated by a deterministic 16-bit LCG. We have executed R = 2000 APQKE handshakes per SGN configuration and logged the public transcript (in particular, M1 containing NSGN i ) and the resulting root-key material. We compared three builds on the same platform: (i) OS-only randomness ( USE_TPM=0 ) and (ii) TPM-seeded 

randomness ( USE_TPM=1 ), and (iii) TPM-PCR (TPM-PCR in Fig. 8(c)), which adds a fail-closed TPM gate before APQKE use any randomness. Concretely, the SGN requests a short secret Kgate (16 bytes) from the TPM; this value is sealed to the platform’s measured-boot state (TPM-PCRs are registers that store hashes of boot components). If the boot state matches a known-good baseline, the TPM releases Kgate ; otherwise, the request fails. The SGN then XOR-mixes Kgate into the per-handshake seed used by APQKE (nonce generation, ML-KEM key generation, and encapsulation coins) and aborts the handshake if Kgate cannot be obtained. In (i) and (ii), the LCG shim is positioned after the seeding source (OS or TPM), so it replaces the bytes returned to APQKE regardless of where the seed was originally sourced. The shim maintains a nominal 16-bit internal register as in Fig. 8(b) and updates it using st j+1 = ( a · st j + c) mod 2 16 ,with (a, c ) = (25173 , 13849) , outputting each byte as the low 8 bits of the updated state. Because the protocol observes only byte outputs, the low-byte projection produces only 28 distinct observable streams. After observing the first byte of NSGN i ,the attacker directly identifies the corresponding observable stream. Although 28 internal states remain consistent with that byte, they form an equivalence class whose elements generate an identical output stream and therefore provide no additional attack resistance. Fig. 8(b) visualizes this internal-state aliasing. This LCG thus serves as an intentionally weak, 8-bit-observable diagnostic model for validating end-to-end key-recovery propagation and for evaluating the effectiveness and placement of mitigation mechanisms. Given a recorded transcript, the attacker identifies an observ-able stream representative consistent with the observed NSGN i

prefix and replays the APQKE protocol offline while forcing the same deterministic RNG stream. This regenerates the SGN’s RNG dependent computations for nonce generation, ephemeral ML-KEM key generation, and encapsulation randomness, enabling the reconstruction of both ML-KEM shared secrets and, thus, the APQKE-derived root key. The attacker does not need to recover the unique 16-bit internal state because every state within the identified equivalence class generates the same protocol visible byte stream. Across the R = 2000 logged runs, the attacker succeeds with overwhelming probability, as shown in Fig. 8(c), for the OS-only and TPM-seeded builds. It does not by itself reveal chain keys from an already completed honest bootstrap, because initialization also mixes the fresh X25519 secret Z0. If the RNG subversion affects X25519 key generation, DH secrets become predictable and post-compromise recovery is compromised. 

E. Discussion and Limitations 

APQKE-DR offers a practical post-quantum-initialized se-cure channel for smart grid endpoints. ProVerif analysis shows the APQKE handshake keeps RK 0 secret and resists active attacks like key substitution and replay. Since APQKE runs only during setup (e.g., initial association or after state loss), its communication overhead is spread over long-term operation. In

ANSI C12.22 and DNP3 shim tests show the post-quantum handshake dominates setup cost, while ratcheted protection stays lightweight and requires no app. layer changes. Although we implement and evaluate APQKE-DR in a smart grid setting, the core construction is not tied to ANSI C12.22, DNP3, or any specific smart grid architecture. It applies to deployments with provisioned endpoint identities, managed backends, long-lived encrypted sessions, potential reboot or state loss, and a need for post-quantum initial key establish-ment combined with lightweight per-message key evolution. Examples include industrial control and SCADA, water and gas metering, remote environmental monitoring, edge-IoT and medical devices, transportation infrastructure, and other critical infrastructure. In these settings, APQKE-DR can protect existing application payloads using a security layer, as in our smart grid prototypes. However, domain-specific validation is required for each domain before large-scale implementation. EAS results show that long-session security depends on the quality of endpoint randomness and RNG-path integrity. In the controlled early-boot model, RK 0 is recoverable during the injected weak-RNG window, with T inj 0.5 ≈ 2000 ms at 

τ = 0 .5. TPM seeding blocks recovery across tested delays with minimal latency impact, but cannot stop downstream RNG substitution, where APQKE accepts attacker-controlled bytes and output-only checks can still look normal. VI. C ONCLUSIONS 

We presented APQKE-DR and evaluated its performance and resilience to endpoint randomness failures using EAS as proposed. The protocol combines authenticated post-quantum key establishment with an X25519 Double Ratchet, whose post-compromise recovery relies on classical assumptions. The prototype integrates beneath ANSI C12.22 and DNP3 without changing application payload formats. It achieves a 13 

median confirmed handshake completion time of 1.990 ms and adds 31 B per message. Under fresh randomness and ideal cryptographic primitives, ProVerif verifies the modeled secrecy and authentication properties. The EAS experiments show that these properties can be undermined when endpoint randomness fails. In the tested cases, predictable randomness allowed recovery of the initial root key from public handshake transcripts. TPM seeding prevented recovery in the tested early-boot cases but did not prevent RNG substitution after seeding.
