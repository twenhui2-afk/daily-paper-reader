## Abstract 

Scene graph generation (SGG) aims to detect objects in an image and predict the relationships between them. The stan-dard PredCls, SGCls, and SGDet settings show how much performance drops without ground-truth boxes and labels, but not where or why a model fails. Knowing this would allow fixing a model where it fails, without retraining. We propose RoHa-SGG (Ro ot-cause-guided Ha rness optimiza-tion for SGG ), which extends agentic harness optimization to SGG. It optimizes the harness, the inference code around a frozen SGG model. RoHa-SGG has two main LLM agents. A root-cause analysis (RCA) agent finds the components where the model fails and diagnoses why, and a proposer agent searches for a harness that fixes these causes. We evaluate RoHa-SGG on Visual Genome and PSG with representative two-stage, one-stage, and multimodal-LLM SGG models. The analysis shows that the components where ground-truth triplets are lost differ across models and datasets. RoHa-SGG improves every metric on all five model–dataset combi-nations. Graph-constrained R@100 and mR@100 rise by up to 15.8 and 26.4 points for the multimodal LLM and by up to 3.6 and 10.1 points for the two-stage and one-stage models. With root-cause guidance, the harness search reaches the final score of an unguided search up to three times faster.

## 1. Introduction 

Scene graph generation (SGG) describes an image as a set of (subject, predicate, object) triplets, such as (man, rid-ing, horse), over the objects it contains [22, 51]. Most SGG models follow one of three architectures: two-stage models first detect objects and then classify a predicate for each candidate pair (REACT++ [33]), one-stage models pre-dict objects and predicates together in a single DETR-style pass [6] (EGTR [18]), and multimodal large language mod-els (MLLMs) write the whole graph as text (R1-SGG [9]). Whatever the architecture, a ground-truth triplet counts as a match only if it passes five components: a correct box and name for both objects, a proposal for the pair, the correct predicate, and a rank within the top K. SGG is usually evalu-ated in three settings [51], which give the model ground-truth boxes and labels (PredCls), boxes only (SGCls), or neither (SGDet). Comparing the three shows how much a model depends on the given boxes and labels, but not at which component it loses ground-truth triplets. A model can fail at any of the five components, and where it fails differs by model and dataset (Fig. 1, left). Following TIDE [3] and Diag-HOI [63], we measure this with the same procedure for all three models. We correct components with their ground truth (the true boxes, names, pairs and predicates, and an ideal ranking) and attribute the recovered recall to each component (Fig. 3). In graph-constrained ( GC )R@20, the missed ground-truth triplets spread over several 1arXiv:2611.27529v1 [cs.CV] 20 Nov 2026 components, and REACT++, EGTR and R1-SGG all lose the most at the pair component. On VG150, the MLLM R1-SGG also loses 27.9 points at the box component, against 7.5 for each classic model. R1-SGG loses nothing at the rank component, where the classic models lose 11.6 to 16.5. On PSG, REACT++ and R1-SGG both lose more at the predicate component than on VG150 (19.6 and 16.6 vs. 16.1 and 9.7 points). A method that targets a single component therefore recovers only part of the missed triplets, and one that helps one model or dataset may not help another. Earlier SGG analyses measure only parts of this, such as pair recall [46], what the detector can reach [37] or separate object, pair and predicate scores [30], or substitute ground truth in a fixed order [14]. The weaknesses these analyses reveal are then usually fixed by retraining the model, for example with a new pair proposal module [46]. Retraining, however, is costly and must be repeated for every model and dataset. We instead optimize the harness ,the inference code that prepares the model’s input, calls the model, runs external tools, and post-processes and ranks the output. Because it handles every step from the image to the final scene graph, the harness can reach every component without changing the model. Harness optimization has recently been shown to work for LLM systems [24] and, in concurrent work, for video understanding and embodied agents [23, 28]. It has not yet been applied to SGG. The space of possible harnesses is large, and scoring each candidate harness means running the model on a large image set. The search is therefore ex-pensive and can afford only a few candidates. These few candidates should target where the model actually fails. Re-cent harness optimizers diagnose failures by reading an LLM agent’s execution traces, such as its prompts, tool calls and intermediate reasoning [7, 36, 47]. A frozen SGG model produces no such trace. Its output shows which ground-truth triplets are missing, but not where or why they were lost. We therefore measure where, component by component, and then test why. We introduce RoHa-SGG (Ro ot-cause-guided Ha rness optimization for SGG ), which uses this per-component di-agnosis to guide the harness search (Figs. 1 and 2). It has two LLM agents. A root-cause analysis (RCA) agent finds where and why the model loses ground-truth triplets, using the same procedure for every model and dataset. It splits the missed triplets over the five components with Shapley values and tests each suspected cause with an intervention whose effect it predicts before running it. A proposer agent then searches for harnesses that fix the diagnosed causes first, rather than exploring the code space without direction. The search runs in rounds, and before each round the RCA agent analyzes the current best harness again, so the proposer always works on the causes that remain. We evaluate RoHa-SGG with REACT++, EGTR and R1-SGG on VG150 [22, 51] and PSG [52]. Without retraining the SGG models, the harness found by each search improves every metric on the official test sets of all five model–dataset combinations (Tab. 2). GC R@100 and mR@100 rise by up to 15.8 and 26.4 points for R1-SGG and by up to 3.6 and 10.1 points for REACT++ and EGTR. Diagnosing first also makes the search faster. To measure this, we run three searches with the same loop, adapted from Meta-Harness [24], and the same number of iterations. The unguided search uses only the loop, the knowledge-guided search adds a human-written guide based on the SGG literature, and the RCA-guided search adds the root-cause analysis. On REACT++ and EGTR, the RCA-guided search reaches the final score of the other two searches after only 5 and 4 of 12 iterations (Fig. 7). Candidate harnesses guided by the diagnosis also reduce the error they target more often. In the first round, 60% of them lower the error of their target component, compared with 41% when the targets are reassigned at random. In summary, our main contributions are as follows: • We propose RoHa-SGG, the first agentic harness optimiza-tion for SGG. It improves a frozen SGG model without retraining it by searching over the inference code around it, guided by an analysis of where and why the model fails. • We introduce a root-cause analysis for SGG that splits each model’s missed ground-truth triplets over five com-ponents with order-independent Shapley values and tests suspected causes with interventions. It reveals that models and datasets lose ground-truth triplets at different compo-nents. • With two-stage, one-stage and multimodal-LLM SGG models on VG150 and PSG, RoHa-SGG improves every metric on all five model–dataset combinations. On VG150, root-cause analysis makes the search up to three times faster than unguided and knowledge-guided searches. 

## 2. Related Work 

Scene graph generation. SGG models include two-stage methods that detect objects first and then predict their pred-icates [33, 57, 61], one-stage methods that predict objects and predicates together with a DETR-style decoder [18, 26], and multimodal LLMs that write the graph as text [9, 11]. Most existing methods improve these models by training them, for example with predicate debiasing and long-tail learning [38, 45, 58], open-vocabulary training [8] or rein-forcement learning for MLLMs [9, 11]. This training must be repeated for every model and dataset. Without retraining the SGG model, we instead search over the whole inference code around it, so that the fix targets the components where each model fails on each dataset. 

Error and root-cause analysis. In computer vision, error diagnosis tools have been built for object detection [3, 15], temporal action detection [2] and human-object interaction detection [63]. They fix each error type with an oracle and measure how much the score rises, as TIDE [3] does for false positives, missed objects and localization errors of de-tectors. For SGG, earlier analyses each cover part of where ground-truth triplets are lost, such as pair recall [46], detec-tor reachability [37], metrics that separate object, pair and predicate quality [30] and ground-truth substitution in a fixed order [14]. Outside vision, related methods identify which agent caused a failure in LLM multi-agent systems [60], ana-lyze the root causes of cloud incidents with LLM agents [49], and diagnose approximate nearest-neighbor search to re-design it automatically [62]. When ground truth is substi-tuted in a fixed order, the measured contribution of each component depends on that order [3], and the module most responsible for a failure is not always the best place to fix it [55]. We measure all five components for every model and dataset with one protocol and split the gain of fixing them with order-independent Shapley values [42], as Shap-leyFlow [54] does for the modules of agentic workflows. We then test each suspected cause with an intervention whose effect is predicted before it runs. 

Agentic harness optimization. LLMs can compose vision models and tools into programs [13, 43]. Such programs are usually designed manually, as in a training-free pipeline that detects human-object interactions with an MLLM [5]. Instead of manual design, other work lets LLMs optimize prompts and LM pipelines [1, 21, 56], programs [41] and agent designs [16, 59] automatically. Meta-Harness [24] extends this to the whole harness of an LLM system, and concurrent work applies harness optimization to video under-standing [10, 28], vision-tool pipelines [12] and embodied agents [23]. These optimizers mostly find what to fix by reading the execution traces of an LLM agent, such as its prompts, tool calls and reasoning [7, 24, 36, 47]. An SGG model outputs only the scene graph, without such traces. We extend agentic harness optimization to SGG and guide the search with root causes measured for each component. 

## 3. Method 

RoHa-SGG has two LLM agents (Fig. 2). The RCA agent measures where a frozen SGG model loses ground-truth triplets and tests the suspected causes with interventions (Sec. 3.2). The proposer agent then searches for harnesses that fix these causes first (Sec. 3.3).

3.2. Root-Cause Analysis 

Errors per component. A ground-truth triplet counts as a match at K only if it passes five components, a box with IoU ≥0.5 (box ) and a correct name ( name ) for both objects, a proposal for the pair ( pair ), the correct predicate ( predicate )and a rank within the top K (rank ). To measure how many triplets a harness loses at each component, we correct its output with ground truth. Let T be the set of the five compo-nents. For a subset S ⊆ T , v(S) is the GC R@ K or mR@ K

of the harness after the components in S are corrected, so 

v(∅) is its unchanged recall. For example, v({box }) adds the missed ground-truth boxes and keeps everything else as predicted. Following TIDE [3], one can correct a sin-gle component s and measure how much the recall rises, 

∆s = v({s}) − v(∅). This misses triplets that are lost at more than one component. For example, a triplet whose subject has no box is recovered only when both its box and its pair are corrected. Neither ∆box nor ∆pair counts it, so the single-component gains do not add up to the missed recall. Correcting the components one after another in a fixed or-der [14] counts it, but attributes it entirely to the component corrected last, so the result depends on the order. The five components can be corrected in 5! = 120 orders, and on the images of the search split the component with the largest share changes in up to half of them. For example, in pipeline order (box, name, pair, predicate, rank), the box component receives nothing for any model. Correcting boxes alone re-covers no ground-truth triplet. We therefore split the gain of correcting all components, v(T ) − v(∅), with Shapley values [42], which average the gain of adding s over all 120 orders. RCA agent. From these errors per component, per-image records and a literature guide, the RCA agent writes candi-date root causes, each a hypothesis about why triplets are lost at one component. It tests each cause with an intervention (e.g . adding boxes from an external detector). Before each intervention, it writes down the expected direction and size of the change in the metric, so that a cause is accepted only when the predicted change appears. A cause is confirmed 

if the change has the predicted direction and at least half the predicted size, its paired bootstrap 95% interval on the search images excludes zero, and it has the same sign on the check set, a small image set disjoint from the search split (Sec. 4.1). Otherwise, it is kept as an estimated cause. For each cause, the agent records the component, image evidence, confirmation experiment and expected direction of the fix. It then ranks the causes and states a reason for each rank (Fig. 2). Another LLM agent then reviews the whole analysis. It can send the analysis back to the RCA agent for correction at most twice. The RCA agent reads only records of the search images and the check set, and never sees the selection or test images. After each round r, it analyzes the new best harness hr in the same way, and the next round works on these new causes.

It may also train small add-on modules on training images while M stays frozen, for example a calibration that rescales the model’s predicate scores or a light head, a small classifier on the model’s features.

A cause-guided candidate receives one diagnosed cause from the RCA agent and writes a harness that fixes it. It starts from a parent harness, which is an earlier candidate of the search. In the first iteration of a round, all three candidates are cause-guided. In the next two iterations, two are cause-guided, and the third is a 

free candidate. A free candidate receives no cause, so it can explore any change to the harness. In the last iteration, two candidates are again cause-guided, and the third merges the fixes found by the round’s cause-guided candidates into one harness. A cause is not given again once its error is fixed or after two attempts that do not reduce it. Before scoring, a reviewer agent, separate from the proposer, checks each candidate’s code. Automatic checks also ensure that the harness follows its inference condition, for example that a single-pass harness calls M only once and that no harness reads ground truth. 

Ranking candidate harnesses. For each candidate harness, we measure its gain over the baseline h0 on the six primary metrics ( GC R@ K and mR@ K, K ∈ { 20 , 50 , 100 }) on the search split. A candidate ranks higher when more of these gains have an image-paired bootstrap 95% interval above zero. Among candidates with the same count, the one with the larger gain in the score μ (Eq. (1)) ranks higher. If two gains in μ differ by less than 0.3 points, the gain at K=50 decides, and then the gain at K=20 . The free candidates of the proposer also use this ranking to choose their parent harness. Among earlier candidates other than the current best, they pick the one with the highest ranking score plus an exploration bonus, which shrinks the more often that candidate has already served as a parent (an upper-confidence rule). 

Rounds and final selection. Each search runs three rounds of four iterations, 12 iterations in total. A candidate harness is promoted if it raises at least one primary metric on the search split and no other primary metric drops significantly. Among the promoted candidates, the main harness of each search is chosen by the same ranking on the selection split. No agent sees these images during the search, so the choice does not depend on the images that guided it. 

## 4. Experiments 

4.1. Experimental Setup 

Models and data. We use the publicly released weights of one model per architecture, the two-stage REACT++ [33], the one-stage EGTR [18] and the multimodal LLM R1-SGG [9] (base networks in Tab. 2). No PSG checkpoint is released for EGTR, so VG150 [22, 51] and PSG [52] give five model–dataset combinations. For each combination, we run an RCA-guided search under the single-pass and the multi-pass condition (Sec. 3.1). To measure the effect of root-cause analysis, the VG150 single-pass searches of the three models are also run as unguided and knowledge-guided searches (Sec. 4.4). All agents use Claude Opus 5.5 at maximum reasoning effort. 

Splits. The search split scores every candidate harness, and the agents see its per-image records. The selection split is hidden from all agents. After the search, it re-scores the promoted candidates to pick the main harness among them (Sec. 3.3). The test split is the official test set. A small check set lets the RCA agent repeat each confirmation experiment on images outside the search split (Sec. 3.2). On VG150, the search (2,500 images), check (500) and selection (1,000) splits are disjoint subsets of the official validation set and contain no image from the training set of any VG150 model. PSG has no official validation set, so its search (791), check (150) and selection (997) splits come from its official training set. We use all 26,446 VG150 test images and all 2,177 PSG test images with ground-truth triplets. 

Metrics. Following the standard SGG evaluation proto-col [9, 44], we report graph-constrained ( GC , one predi-cate per subject–object pair) R@ K and mR@ K at K ∈{20 , 50 , 100 }, averaged over images. For a fair comparison, we score all models with the same evaluation code. F@100 is the harmonic mean of R@100 and mR@100 [58]. On PSG, a predicted box matches a ground-truth box if their IoU is at least 0.5 and their labels agree, as in the evalua-tion of REACT++ and R1-SGG. We also report detection AP50 [27]. All intervals are 95% intervals from an image-paired bootstrap.

4.4. Effect of Root-Cause Analysis 

To measure the effect of root-cause analysis, we compare three search settings on the VG150 single-pass searches of all three models. All three settings run 12 iterations with three candidate harnesses each, and they share the model interface, tools, scoring and selection rule. The unguided search uses only the search loop adapted from Meta-Harness [24], so its proposer receives no diagnosed causes. The knowledge-guided search also gives the proposer a human-written guide based on the SGG literature. The RCA-guided search instead gives the proposer the causes diagnosed by the RCA agent, as described in Sec. 3. 

Search efficiency. On REACT++ and EGTR, the RCA-guided search reaches the final score of the unguided and knowledge-guided searches after only 5 and 4 of 12 itera-tions, up to three times faster (Fig. 7). For EGTR, it leads at every iteration, almost entirely through GC mR@100. For REACT++, the gap opens with the first re-diagnosis. During the second round, the new causes lift the score from 4.1 to 6.9, while the other two settings stay nearly flat. Candidates guided by the diagnosis also reduce the error they target more often. In the first round, 60% of them lower the error of their target component, against 41% when targets are randomly permuted within a search (permutation test, p < 0.001 ).

4.5. Discussion and Limitations 

When does the analysis help? The analysis helps most when a model’s errors cannot be seen from its output or its recall alone. For R1-SGG, the three settings end within 1.7 points on the search split. R1-SGG leaves many objects without a box, an error that is visible in its output. Every setting therefore adds detector boxes, and the analysis adds little beyond that. REACT++, in contrast, also loses triplets at object names, an error that its recall alone does not show. Only the RCA-guided search recovers these name errors (52% of its recovered triplets), through a candidate that read the errors per component, and it raises GC mR@100 two to five times as much as the other searches. 

Inference and search cost. Single-pass harnesses add under 1 ms per image for EGTR, about 13% for R1-SGG and under 1 s for REACT++, which calls external detectors (Tab. 3). A search costs $263–376 in API fees, including $62–105 for the analysis (Tab. 4). The analysis pays for itself. On REACT++ and EGTR, the RCA-guided search reaches the final score of the other two searches early. Up to that point, it spends less than those searches spend in total, including all its analysis costs. 

Limitations. Each search runs once, so the intervals reflect image, not run-to-run, variation [4]. Other LLM agents and the PredCls and SGCls settings are future work. 

## 5. Conclusion 

We presented RoHa-SGG, the first agentic harness opti-mization for SGG. Its RCA agent finds where and why a frozen SGG model fails, and its proposer agent automati-cally searches for harnesses that fix them without retraining. The analysis shows that models lose ground-truth triplets at different components. The searched harnesses improve every metric on all five model–dataset combinations, across two-stage, one-stage and multimodal-LLM models. The gains reach 15.8 GC R@100 and 26.4 GC mR@100 points.
